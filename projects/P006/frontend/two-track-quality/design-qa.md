# 두 트랙 품질 검증 설계

원씽: 외부 식별 대기와 현재 USD 검증을 분리한다.

## 프로세스·액터

트랙A: 증거 검토자 → 요청경로 판정 → 최소3개 항목 확정 → 자료 수신 대기 → 장비/승인설계 동일성 확인 → 별도 BLOCKED 해제 검토. 자동 외부 발송 없음.

트랙B: 자동 구조 검증기 → 공통 베이스(소스SHA+prim) → Variant/구성(선택+하위 오버라이드) → 개별 자산의 경계·원점·포트 → 분야 검토자 승인 → 누적 게이트 승격. 트랙A 응답을 필수 선행조건으로 두지 않음.

## 상태·증거

USD_CONNECTED → GEOMETRY_VERIFIED → PHYSICAL_VERIFIED → FUNCTION_VERIFIED → PORT_VERIFIED → ASSET_READY. REAL은 별도 실제 장비 읽기 전용 관찰 게이트.

기존10종 참조 레이아웃 READY는 그대로 보존하며 새 엄격 검증 집계에 혼합하지 않음. GEOMETRY는 토폴로지뿐 아니라 장비 종류와 형상/설계 근거의 대조가 필요.

contract.json이 상태 설계, quality-gates.py가 실행 정책, two-track-generate.py가 보고서 생성기다. 원본 registry/USD/DB는 읽기 전용. 새 감사 장부만 JSON으로 생성하며 배포 빌드·서비스 재시작 없음.

## 페이지·기능

한 페이지: KPI7개, 트랙A/B 탭, ID·이름 검색, 공유 베이스 커버 순서, 개별10항목 검증, 도움말·화면설계·QA·다음업무·업무길잡이·전체업무.

## 테스트

가짜PASS·출처없는PASS·오래된SHA·부분누적상태·SIMULATED REAL 위조를 거절. 기반SHA가 바뀌면 승격 무효. 목록58/666 및필터·상세10항목·모바일·다운로드 링크를 브라우저로 검증. 입력은 기존연결 JSON, 출력은 별도 감사 JSON. 업무 데이터/PLC쓰기0.

## 다음 바위

깨달음: 같은 베이스의 형상 검사를 공유할 수 있어도 치수·장착·작업물·공정·포트 증거까지 자동 공유할 수는 없다.
