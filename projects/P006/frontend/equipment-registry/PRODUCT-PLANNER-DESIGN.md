# 신규 제품 생산 설계 화면

## 목적과 범위

`product-planner.html`은 신규 제품의 주요 부품, 부지·공장, 공정·운송, 실행 검토를 한 화면 흐름으로 입력하는 독립 페이지입니다. 기존 생산망 화면을 iframe으로 포함하지 않으며, 헤더와 하단 링크를 통해 `production-network.html`에 이동할 수 있습니다.

이 화면과 예시 입력은 편집 가능한 기능 시연입니다. 시간·거리·수량은 입력자가 제공한 가정이며, 실제 공정 능력·기계 물리·운송 성능을 검증한 결과로 표현하지 않습니다. 실행 화면의 SVG는 생산 흐름을 설명하는 개략도입니다.

## 단계와 주요 데이터

| 단계 | 입력·검토 범위 | 화면 컨테이너 |
|---|---|---|
| 제품·주요 부품 | 제품명, 생산 수량, 기준 출처, 완제품당 주요 부품 수량·조달·담당 공장·확보시간·결합 공정 | `data-panel="product"` |
| 부지·공장 | 실제/가상 부지와 공장, 공장-부지 연결, 선택적 Layout ID | `data-panel="site"` |
| 공정·운송 | 공정 작업·종류·대상 부품·공장·선행 공정·시간 기준, 부품별 공장 간 경로·거리·운송·하역시간 | `data-panel="process"` |
| 실행 | 검증 결과, 시연 배속·애니메이션·단계 진행, 요약 지표, 공정별 설비·작업물 연결표, 순서별 실행 로그 | `data-panel="run"` |

제품 단계에는 모델 현황표를 제공하며 완제품, BOM 주요 부품, 명시적으로 지정한 설비 카탈로그 후보와 범용 참고 자산의 USD/GLB 경로 연결 상태를 보여줍니다. 경로 입력, 카탈로그 등록, 공정 적합성은 각각 다른 증거이므로 표에서 상태를 구분합니다. 설비 후보와 범용 참고 자산은 계획에 자동 반영되지 않습니다. 모델 확보 목록 CSV는 현재 계획의 모델 경로·수량·상태와 다음 조치를 내보냅니다. `자동차 모델 실사 결과` 링크는 서버 원장 724건과 모델 인벤토리 실사 JSON을 시각화하고 제품 모델 미확보와 참고 설비 GLB를 분리합니다. 공정·운송 단계의 `모델 경로 점검`은 계획 연결 및 카탈로그 참고 GLB의 same-origin HTTP 응답과 `glTF` 헤더만 검사하며, 외부 URL/서버 내부 USD 경로는 읽지 않습니다. 통과는 파싱·제품 적합성·조립 검증 승인이 아닙니다.

실사 화면에서 `설비 후보 실제 3D 로딩 검증`으로 진입하면 계획 저장 없이 고정된 5개 설비 후보를 GLTFLoader로 파싱하고 bounds 기준으로 화면에 배치합니다. GLB 내장 Animation Clip이 실제 존재할 때만 재생을 활성화하고, 클립이 없으면 없음으로 표시합니다. 이 테스트는 자동차 부품·공정 적합성이나 실설비 가동 검증을 뜻하지 않습니다.

주요 부품 수량은 완제품 1개 기준입니다. 생산 수량을 곱한 총 소요량과 혼동하지 않도록 UI 도움말과 표 설명에서 기준을 반복해 안내합니다. 공정 데이터에는 종류(MAKE/PROCESS/ASSEMBLE/INSPECT/DISPATCH), 대상 부품(공란은 완제품), 공장, 선행 공정, 소요시간 및 시간 기준(BATCH/UNIT)이 포함됩니다. 같은 부품의 여러 공정은 표 행 순서대로 진행합니다. 조립은 지정된 주요 부품 전체를 소비하며, 조립 단계를 여러 개 둘 수 있습니다. 최종 DISPATCH 단계는 모든 결합 공정에 의존해야 합니다.

## 연결 계약

## 부지별 동시 카메라

`product-planner-multiview.js`는 하나의 전체 실행 시각을 공유하되 부지 카드마다 독립 카메라 상태(회전·확대·표시 대상)를 유지한다. 카메라 모드는 `equipment`(해당 부지 설비), `all`(설비+현재 표시 작업물), `workpieces`(작업물·완제품)다. 장면 객체 집합에서 부지와 종류를 먼저 필터링한 다음 해당 부분집합의 Bounds로 카메라를 맞춘다. 따라서 12개 가상 모듈의 큰 분산 Bounds가 설비만 보는 구도의 기준을 축소시키지 않는다. 필터는 렌더 표시만 제어하고 실행 상태·관계·계획 데이터는 변경하지 않는다.

페이지는 `product-planner-core.js` 다음 `product-planner.js`를 로드합니다. 다음 ID는 동작 스크립트의 DOM 계약으로 유지해야 합니다.

| 영역 | ID |
|---|---|
| 상태/제품 | `appNotice`, `productSelect`, `productName`, `quantity`, `productSource`, `productOverview`, `modelCoverageSummary`, `modelCoverageRows`, `downloadModelAcquisition`, `validateModels`, `modelValidation` |
| 표 본문/추가 | `partsBody`, `addPart`, `sitesBody`, `addSite`, `factoriesBody`, `addFactory`, `processesBody`, `addProcess`, `routesBody`, `addRoute` |
| 흐름/실행 | `flowOverview`, `validationList`, `runScene`, `runMetrics`, `eventLog`, `runStart`, `runPause`, `runReset`, `animationEnabled`, `speed` |
| 저장/도움말 | `savePlan`, `loadPlan`, `exportPlan`, `importPlan`, `savedPlans`, `saveServer`, `saveStatus`, `help` |

단계 탭은 `button[data-tab]`과 `section[data-panel]`의 값으로 연결합니다. 선택 상태는 키보드 조작과 보조기기에서도 식별할 수 있도록 버튼 상태를 갱신해야 합니다. 표 데이터는 각 `tbody` 안에 행 단위로 생성하며, 삭제 등 행 작업은 개별 행 문맥을 유지해야 합니다.

## 디자인·반응형 기준

- KRDS 계열의 명확한 제목 위계, 대비가 있는 네이비 헤더, 청록색 주요 동작, 밝은 배경과 절제된 테두리를 사용합니다.
- 각 단계는 넓은 단일 작업 영역으로 배치하고, 실행 검토에만 도식과 요약 패널의 2열 구성을 사용합니다.
- 실행 검토의 `전체 공정 애니메이션 재생`은 일정 검증 → 필요한 시연 3D 준비 → 0분부터 재생 순으로 수행하며, `일정만 실행`은 2D 시간표/흐름도로 구분합니다.
- 표는 작은 화면에서도 필드 순서를 유지하며, 독립 가로 스크롤 래퍼를 제공합니다.
- 부지별 3D 카메라는 기본 `설비·작업물` 동시 표시를 사용하고, 설비만 또는 작업물만 표시하는 전환을 제공합니다.
- 폼 입력에는 명시적인 label을 연결하고, 상태·요약 영역은 `role="status"` 또는 `aria-live`로 동적 변경을 알립니다.
- `production-workflow.css`의 공통 기반을 재사용하되 제품 설계 스타일은 `.pp-` 네임스페이스로 구분합니다.

## 검수 체크리스트

1. 제품→부지→공정→실행 탭과 링크가 각 독립 패널을 표시합니다.
2. 주요 부품의 수량 설명이 완제품 1개 기준으로 유지됩니다.
3. 모든 필수 DOM ID가 스크립트에 의해 조회 가능하고, 저장 관련 버튼과 입력이 존재합니다.
4. 620px 이하에서도 전체 페이지가 넘치지 않으며, 넓은 표는 해당 래퍼 안에서만 가로 스크롤됩니다.
5. 시연과 실측·물리 검증을 구분하는 안내가 제품, 운송, 실행 화면에 표시됩니다.
6. 도움말과 기존 생산망 이동 링크가 페이지 안에서 접근 가능합니다.

## 외부 RC Car USD 구조 후보 연결 · 2026-09-26

제품 단계에 USD 구조 검토 카드와 `product-planner-rc-car-structure.html` 근거 화면, `product-planner-rc-car-assembly.html` 실제 Mesh 3D 검토 시연을 연결한다. 원본 USD의 36 Mesh를 6개 category node 아래에 배치한 28.2 MB GLB를 버튼 선택 시 로드한다. 시연은 명시된 4개 구조 검토 단계의 사용자 정의 이동이며 실제 USD joint/animation이 아니다. 설계·범위 계약: `PRODUCT-PLANNER-RC-CAR-STRUCTURE-DESIGN.md`.

시연은 입력된 사용자 시간 기준의 프로세스 애니메이션 개략도입니다. 실제 설비의 기계·3D 시뮬레이션과 별개이며 이를 대신하지 않습니다. 이 문서는 화면 설계 계약입니다. 저장 형식, 검증 알고리즘, API·DB 연결과 실제 브라우저 동작은 실행 스크립트 및 통합 검증 범위에서 별도로 확정합니다.

## 실행 검토 · 실제 설비 동작 후보 Pilot

실행 검토에는 시간표의 모든 조달·공정·운송 단계를 정렬한 `공정별 설비·작업물 연결표`가 있다. 각 행은 작업물/수량, 부지·공장, 계획시간, 설비 Asset ID와 USD/GLB 경로 입력 상태, 현재 동작 범위를 보여준다. 경로 입력 상태와 런타임 모델 로딩 성공은 별도로 표시해 혼동하지 않는다. 표에서 현재 실행 중 단계도 시간표와 함께 강조한다. 연결된 설비 GLB와 설명용 `FUNCTIONAL_DEMO` 모듈은 Process ID 및 입력 시간표를 공유하여 설비 인근 시연 작업점, 부지 간 운송, 조립 위치 순으로 표시한다. Port 계약이 없는 단계에서 모듈이 설비 내부를 실제 통과한다고 간주하지 않는다. GLB에 Animation Clip이 없으면 설비는 정적이며 미배정 설비는 주황 작업점만 표시한다. 자동차 부품 USD/GLB와 실제 BOM·치수·접촉·공정 적합성은 검증되지 않았다. `E096`은 별도 `bed / ram / tool` 구조 및 생성 Box Proxy 기반 `FUNCTIONAL_DEMO` Pilot 링크를 유지한다. 상세 계약은 `PRODUCT-PLANNER-E096-PRESS-CYCLE.md`, QA는 `PRODUCT-PLANNER-QA.md`에 있다.

공정 입력 단계는 `공정별 설비 Asset 후보` 표에서 작업 종류/공정명으로 검색 범주를 제안한다. 후보 목록은 현재 Asset Registry의 실제 category 및 3D manifest상 GLB 경로가 있는 자산만 사용하고, 사용자가 범주와 Asset을 선택해 기존 모델 입력란으로 복사한다. `DISPATCH`와 구매·운송 이벤트는 설비 후보에서 제외한다. 범주 제안은 검색 편의를 위한 휴리스틱이며 작업물/차종 적합성 증거가 아니고, GLB 경로 입력도 파일 파싱·동작 검증이 아니다. 사용자가 모델 연결 적용을 누르기 전에는 계획 변경을 확정하지 않는다. 후보 원장/관계/Flow/애니메이션 상태를 자동 승인 또는 승격하지 않는다.

### 공정 시간 연동 설비 표시

- 공정에 연결되어 로드된 설비 GLB마다 3D 패널의 설비 상태 칩을 생성한다. 칩에는 공정명, Asset ID, 현재 상태(대기/현재 작업/완료), 표시/동작 근거를 보여주고 `보기`는 해당 Instance Bounds로 카메라를 이동한다.
- 일정상 활성 공정의 실제 GLB 설비 바닥에 주황색 링 하이라이트를 켠다. 이 표식은 활성 공정 UI 신호이며 기계 가동으로 취급하지 않는다. 선택 가능한 `현재 작업 설비 따라가기`는 활성 공정 단계가 바뀔 때만 카메라를 이동한다.
- GLB 내장 Animation Clip이 있으면 Three.js `AnimationMixer`를 사용해 process task의 정규화된 시작/종료 진행률에 따라 Clip 시각을 결정적으로 샘플링한다. 이는 시간표 동기 표시일 뿐 기계 제어·제품 공정 적합성 인증이 아니다. Clip이 없으면 설비는 정적 GLB로 남는다.
- 메인 통합 카메라의 기본 상태는 `현재 작업 설비 따라가기`다. 복수 활성 공정이 있어도 공정 순서가 가장 앞선 GLB 연결 설비 하나를 현재 시점의 대표 설비로 프레이밍하고, 활성 설비 변경 때 카메라를 전환한다. 연결 설비가 없는 공정 사이에는 직전 설비를 유지하고, 완료 때는 마지막 완료된 GLB 연결 설비를 유지한다. 재생 초기화/0분 대기에는 전체 Scene Bounds를 표시한다. `전체 배치 보기`와 설비별 `보기`는 추적을 끄고 사용자 고정 시점을 제공한다.
- 메인 추적 프레이밍은 실제 설비 Holder의 월드 Bounds와 캔버스 종횡비/FOV로 계산하며 여유 계수 1.65를 적용한다. 부지별 카메라도 현재 표시 모드에 포함된 부지 소속 Object Bounds로 별도 FOV fitting을 수행하고 여유 계수 1.32를 사용한다. 두 수치는 화면 가독성용 렌더 기준이며 제조사 설치 이격·안전거리 기준으로 사용할 수 없다.
- 기존 E096 ram 왕복 후보는 Clip이 없을 때만 실행하는 `FUNCTIONAL_DEMO` fallback이다. 다른 GLB의 노드/형상은 Clip이 없다는 이유로 합성 이동시키지 않는다.
- 로딩 세대·Geometry/Material/Texture 정리는 기존 방식을 유지하고, 닫을 때 Mixer action을 멈추고 root cache를 해제한다. 저장 계획·Asset Registry·관계 DB는 이 표시 기능으로 변경되지 않는다.

### 공정 작업점과 모듈 경로 정합

- 공정 Process ID와 계산된 Schedule Task를 공통 키로 사용하여 설비 Holder와 작업물 위치를 같은 공정별 작업점에 배치한다. 작업물은 화면 가독성을 위한 시연용 병렬 이송 레인에서 공정 작업점에 진입·체류·배출한다. 공장 내 후속 공정, 부지 간 운송 Task 및 조립 위치는 같은 공정/일정 키로 연결한다.
- 작업점은 설비 모델 크기와 계획된 공정 순서를 사용해 간격을 계산한다. 가상 작업물은 실제 설비 Mesh 안에 파묻히지 않도록 인접한 시연 레인으로 분리한다. 해당 오프셋은 GLB의 검증된 입출력 Port·작업 Surface 좌표가 아니므로 생산 배치·물리 접촉 승인에 사용할 수 없다.
- `FUNCTIONAL_DEMO`의 가상 주요 모듈은 시간표·수량 기준 경로 시각화로만 취급한다. 모듈 Mesh/형상은 공정 처리에 따라 변형되지 않으며, BOM, 작업물 접촉, 설비 용량 및 차종 적합성은 미검증이다.
- 연결 GLB가 없는 Process는 해당 좌표에 이름이 붙은 주황색 `설비 GLB 미연결 · 작업점` 표식을 보인다. 이 표식은 설비 형상 또는 설비 존재를 대체하지 않는다. 행별 설비 상태도 `미연결`을 유지한다.
- 실제 연결된 GLB 설비는 해당 Process ID에 고정된 동일 작업점에 놓이며, GLB Animation Clip이 있을 때에만 Clip 시각을 공정 시간에 맞춘다. Clip 부재 시 모델은 정적으로 표시한다.
- 화면의 `공정별 설비·작업물 연결표`는 Task별 입력 부품/수량, 위치, 예정시간, 필요 설비 Asset/GLB 상태, 산출물 및 다음 상태를 보여준다. 작업물 모델 미연결/가상 Demo/설비 GLB 미연결은 서로 구분한다.
- 로컬 작업점 배열은 시연 배치이다. 실제 설치 좌표, 접촉/충돌 검증, 기계 작동, 공정·자재 적합성 및 생산 성능 근거로 사용하지 않는다.

## 설비 식별 라벨 및 카메라 Pan · 2026-09-27

- GLB 연결 설비의 3D Holder 위 Sprite 라벨에 설비명, Asset ID, 현재 상태(표시 준비/대기/현재 작업/완료)를 표시한다. 공정 상태 변경 때 표시 문자열이 달라진 경우에만 CanvasTexture를 갱신한다.
- 메인/부지별 카메라는 `pointerdown.altKey`에서 일반 Orbit과 Pan을 구분한다. Alt+드래그는 카메라 목표점만 이동하며 설비/작업물 Transform은 바꾸지 않는다. 메인에서 Pan하면 자동 설비 추적이 중지되며, 추적 체크/전체 배치/설비 보기에서 다시 초기화할 수 있다.
- 각 부지 카메라는 독립 panX/panY를 가지며 카메라 초기화 시 회전·확대와 함께 이동 상태도 초기화한다. 도움말과 캔버스 안내에는 `드래그 회전 · Alt+드래그 이동 · 휠 확대`를 표시한다.

### 미배정 복합 공정 셀 참고 후보

- 미배정 복합 공정은 설비가 없는 상태로 유지하고, 공정별로 필요한 설비 역할군, 카탈로그 GLB Asset 후보 및 근거 공백을 표시한다.
- 검색 후보는 실제 공정 적합성·자동차 제품 대응·설비 세트 완결성 승인으로 취급하지 않으며 저장 계획에 자동 삽입하지 않는다.
- 기존 범주/Asset 선택을 통해 사용자가 후보 입력 후 명시적으로 모델을 계획에 적용하는 흐름을 재사용한다. 배정 후에도 연결 후보 상태 및 미검증을 보존한다.
- 실행 화면의 3D 공정 카드에도 미배정 5개 셀의 필요 역할군, GLB 경로가 있는 자산 원장 후보, 요구사항 근거 공백을 보조 정보로 반복 표시한다. 카탈로그 후보는 계획 데이터에 기록되지 않으며 3D 장비·공정 연결선·애니메이션으로 생성하지 않는다.
- 카드는 공정명/상태, 현재 모델 상태, 제품·부품·부지/공장·시간을 유지한 뒤 요구 설비 정보를 별도 경계선 영역에 놓는다. `설비 미배정/작업점 표시`와 `카탈로그 참고 후보`를 시각·문구로 구분한다.

### 공정 셀 동시 프레이밍

- 자동 추적 및 설비 칩의 `셀 보기`는 공정 설비 Bounds와 현재 공정에 매핑된 부품/가상 작업물 Bounds의 합집합을 카메라 대상으로 사용한다. `consume[]`가 있는 조립 작업은 투입 부품 전체를 포함한다.
- 카메라를 공정 셀로 맞추는 동작은 Scene 객체의 Transform, 일정 시각, Asset 배정에 영향을 주지 않는다. 작업물이 아직 일정상 표시되지 않으면 현재 작업물을 새로 생성하지 않고 설비 Bounds만 사용한다.
- UI 도움말은 공정명/설비 ID/실행 상태 라벨, 드래그 회전, Alt+드래그 Pan을 함께 안내한다. 화면 표시용 프레이밍 값은 물리 정렬·Port 접촉 증거가 아니다.

### 전체 공정 실행과 단일 조립 셀 동기화

- Planner의 실행 broadcaster가 조달·운송·공정 task, 입력 부품, 공장/부지, 지정 설비, 일정 시작/종료, 실행 시각을 snapshot으로 제공한다.
- 같은 Origin의 조립 셀 iframe/탭은 동일 계획 snapshot을 받아 Timeline/HUD에 공정명, 부품, 위치, 지정 Asset, 현재 진행률을 표시한다.
- 현재 task의 `consume` 부품 중 명확히 이름이 매핑된 3개 설명용 Proxy만 조립 일정 중에 수렴한다. 부품이 아닌 작업이나 미매핑 자산은 이동하지 않는다.
- 독립 셀 시연은 명시적인 별도 동작으로 유지한다. 메인 계획 동기화 시에는 계획 시간축을 사용한다.
- E032는 정적 Pilot 장비이며 실제 공정 배정이라고 추정하지 않는다. 동기화는 관계/Flow/Animation 승인 상태를 변경하지 않는다. 자세한 계약은 `PRODUCT-PLANNER-RUN-CELL-SYNC.md`와 QA 항목에 있다.

### 실행 3D 설비 표시 정책

- 공정 설비의 3D Label은 현재 카메라가 추적하는 설비 또는 사용자가 `셀 보기`로 선택한 설비 1개에만 표시한다. 전체 배치 보기에서는 Label을 숨겨 Mesh 가림과 Bounds 오염을 막는다.
- Label은 실제 Mesh 앞에 무조건 그리는 Overlay가 아니라 Depth Test를 사용하는 Billboard다. 카메라 거리와 viewport 크기를 기준으로 고정된 화면 점유 크기를 계산해 근접 줌에서 설비를 덮지 않게 한다. 기준점은 실제 Mesh bounds 상단보다 위에 둔다.
- 현재 추적/선택된 설비 1개의 카드에 공정명, 카탈로그 설비명·Asset ID, 제품명, 대상 부품, 현재 상태와 일정 시간을 표시한다. 실제 모델이 없는 공정은 작업점으로만 남기며 카드는 GLB 동작이나 공정 적합성을 증명하지 않는다.
- Asset/GLB가 없는 공정은 주황 Workpoint 표시로 유지하며, 공정명/미배정 상태는 DOM의 설비 목록에서 확인한다. Workpoint를 실제 설비로 세지 않는다.
- 다부지/다공정 동시 진행은 부지 카메라 카드에서 병렬 확인한다. 전체 배치 카메라는 위치 문맥용이며, 세부 설비 검토는 설비별 `셀 보기`를 사용한다.
- 기존 Instance·Asset ID·공정/Flow 증거·배치·모델 크기는 바꾸지 않는다.

## 전체 공정 카드와 누락 설비 작업점 · 2026-09-28

- 공정 설비 목록은 실행 시작 전, 진행 중, 완료 후 모두 유지하고, 각 공정 카드에 제품, 대상 부품과 수량, 부지/공장, 예정 시간, 설비 Asset 이름/ID, GLB 표시·미연결·로딩 실패 상태를 표시한다.
- GLB가 표시되지 않는 공정도 카드에 포함한다. 실제 Asset 미배정, GLB 경로 미연결, GLB 로딩 실패를 별도 문구로 구분하고 설비가 있는 것처럼 취급하지 않는다.
- 각 카드의 `설비 보기`는 로드된 설비를 확대하고, `작업점 보기`는 미연결 설비의 주황 작업 위치를 확대한다. 카드 목록은 3D Canvas 위에 다열 Grid로 표시한다.
- 자동 추적은 진행 중 활성 공정에만 적용한다. 실행 시작 전과 전체 완료 후에는 전체 배치 Bounds로 복귀한다. 사용자 수동 카메라 조작과 개별 카드의 위치 확인을 보존한다.
- 전체 GLB 8/8 표시와 설비 배정 8/13은 각각 모델 로딩 성공과 공정 설비 매핑 상태이며, 남은 5개를 숨기거나 자동 배정하지 않는다.
- 공정시간, Asset 매핑, Geometry/Scale, BOM, 애니메이션 승인, 배치·DB 저장은 변경하지 않는다.

### 선택 설비 Billboard 가림 방지 보완

- 공정 카드가 제품·부품·부지/공장·시간·설비 상태의 상세 정보를 제공하므로 3D Billboard는 간결한 설비 식별 보조로 취급한다.
- 선택/추적 중인 1개 설비에만 Billboard를 표시한다. 화면 폭은 `min(220px, max(165px, canvasWidth * 0.18))`로 제한하고, 표시 anchor는 Mesh 상단 `max(2.2m, meshHeight * 0.62)` 위로 둔다.
- Perspective 깊이 기반 pixel sizing은 보존한다. 전체 공정 상태는 13개 HTML 카드에서 읽으며, Billboard 문구만으로 미연결 공정을 설비 표시 성공으로 해석하지 않는다.
- 2026-09-28 화면 검수에서 13개 카드와 3D GLB 8/13, 미연결/미표시 5개가 확인됨.

### 후보 GLB 일괄 연결과 전체 공정 3D 준비

- 자동차 예시에는 13개 설비 대상 공정마다 등록 GLB를 가진 대표 시각화 Asset 후보를 둔다. 기존 8개 이름 후보는 보존하고, 복합 셀 5곳은 필요 설비군 중 한 Asset만 대표 표시한다.
- 대표 후보 매핑은 제조 적합성 승인이나 설비군 전체 완비를 의미하지 않는다. 남은 설비군 Asset은 후보 미리보기에서만 표시한다.
- 전체 3D 로딩은 설비 후보를 빈 항목에 반영한 후 사용자 계획 revision/localStorage 저장을 거쳐 진행한다. 사용자 지정된 다른 Asset 연결은 덮어쓰지 않는다. 같은 Asset ID가 저장돼 있으나 경로가 빠진 경우에만 manifest 경로를 채운다.
- 브라우저 localStorage와 Composer API server DB는 별도 저장층이다. 후보 적용은 server DB save를 자동 호출하지 않는다.
- 설비 후보를 바꿀 때 공정이 RUNNING이면 작업을 거부한다. 정지된 경우 수정 계획 기준으로 실행 runtime은 초기화된다.
- 각 실행 카드/연결표/3D 상태는 모델 파싱 실패와 미배정 작업점을 별도로 표시한다.
