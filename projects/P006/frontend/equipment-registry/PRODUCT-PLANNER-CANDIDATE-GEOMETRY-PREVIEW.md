# Product Planner · 미배정 설비 후보 3D 참고 미리보기

일자: 2026-09-28  
화면: `/projects/P006/assets/equipment-registry/product-planner.html#run`

## 설계 범위

미배정 복합 공정 중 하나를 선택하면 Asset Registry에 등록되고 GLB 경로가 확인된 후보 Geometry를 메인 3D 실행 캔버스에 임시 표시한다. 후보는 작업점 인근에 원본 단위/비율로 줄 세워 참고용으로 렌더링한다.

각 항목은 `CATALOG_REFERENCE_ONLY`이며 계획의 공정 설비 Instance가 아니다. 후보 모델을 확인해도 설비 배정, 공정/제품 계획, 저장 데이터, 관계 Evidence, Flow 또는 Animation 검증 상태가 바뀌지 않는다. 후보의 자동차 공정 적합성, 치수, 지그, 처리능력도 미검증 상태다.

Product Planner의 부지별 멀티카메라 캡처에서는 임시 후보를 숨긴다. 따라서 후보 형상을 다른 부지의 실제 Asset처럼 오인하지 않는다. 닫기/전환 시 임시 Geometry·Material·Texture 자원을 폐기하고, 동시 비동기 요청은 generation guard로 오래된 결과를 버린다.

## 남은 5개 공정의 카탈로그 후보

| 공정 | Asset 후보 | 미확인 사항 |
|---|---|---|
| 섀시 모듈 제작 | E121, E135, E148, E123 | BOM, 성형/가공/접합 공법 |
| 차체 투입·조립 기준 설정 | E148, A123, N143 | 차체 구조, 접합점, 지그 |
| 차체·섀시·구동·배터리 결합 | A042, E032, E122 | 순서, 하중, 체결 사양 |
| 내장·조종석·유리 장착 | E032, E146, N143, A203 | 취급/접착/고정 조건 |
| 외장·등화·휠 장착 | A203, E032, E122, A042 | 휠 리프트, 토크, 체결 사양 |

## QA 검수 절차

1. 기존 저장 계획을 열고 `공정 설비와 모듈 흐름 보기`로 실제 할당 GLB를 로드한다.
2. 미배정 공정 5개 각각에서 `후보 모델 미리보기`를 열고 GLB 형상·Asset ID 라벨과 미배정 경고를 확인한다.
3. 닫기/다른 공정으로 전환 후 임시 Scene이 제거되는지 확인한다.
4. 설비 할당 수, 저장 계획, 공장별 멀티카메라 캡처가 변하지 않는지 확인한다.
5. 계획 화면은 읽기 전용으로 검증하고 DB 저장을 호출하지 않는다.

자동 검사: details/multiview JavaScript syntax, Product Planner core tests, multi-view tests. E096 embed test는 오래된 저장소 루트 HTML fixture와 현행 서버 화면의 버전 차이를 나타내므로 본 기능의 회귀 PASS로 사용하지 않는다.

## 검증의 한계

GLB가 로드되어 보이는 것은 카탈로그 자산 존재와 화면 렌더만 뜻한다. 생산 설비 배정, 연결, 충돌, 공정 능력, 기계 동작, 물리 애니메이션을 검증하지 않는다. 후보를 실제로 배정하려면 별도 승인/근거 단계가 필요하다.

원씽: “설비가 사라졌다”는 시각적 혼란을 줄이기 위해 실제 카탈로그 형상은 보여주되 실제 배정 상태는 오염시키지 않는다.  
깨달음: 시각화 후보와 공정에 할당된 장비는 데이터 모델과 화면 상태 모두에서 분리되어야 한다.  
다음 업무 카드: 미배정 5개 공정의 BOM·기능 요구·공법·치수 근거를 모아 후보별 승인/제외 결정을 한다.
