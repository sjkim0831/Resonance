# 통합 생산 작업대 설계 v1

작성일: 2026-10-04 (KST)  
대상: P006 생산 설계 워크스페이스  
상태: 기존 워크스페이스를 보존하는 추가 프론트 경로; 실제 계정 기반 서버 저장은 로그인 세션에 따름

## 1. 목표와 순서

하나의 작업대에서 계획 선택, 품목·설비 탐색, 공정 연결, 공장 배치 확인, 3D 실행, 검토·저장을 순서대로 안내한다. 기존 탭과 저장 모델은 유지하고 `00 통합 작업대`를 새 진입점으로 추가한다.

1. 제품·품목: 제품, BOM, 중간품, 완제품, 부산물 및 연결 자산
2. 부지·공장·배치: 부지/공장 크기·방향·입출구·설비 위치
3. 공정·운송: 선행 순서, 담당 설비, 투입/산출/부산물, 차량, 거리와 경로
4. 설비 스튜디오: 제조사·모델, 참고자료, GLB/USD, 동작 정보
5. 실행·3D: 같은 계획의 시설·설비·운송 시연, 공통 시계와 재생
6. 검토·저장: 계획 검사, 오류 목록, 계정 서버 저장 및 JSON 경로

## 2. 한 화면의 레이아웃

- 상단: 현재 계획 및 Revision, 6단계 이동, 검증/저장 액션
- 좌측 팔레트: 현재 계획의 품목과 설비 검색·유형 필터. 공통 700+ 자산 카탈로그는 기존 스튜디오 검색 화면으로 이동
- 중앙: 같은 앱의 기존 Three.js 렌더러가 그리는 전체 부지·공장·설비·도로/운송 장면, 재생·일시정지·초기화·배속·시간축
- 중앙 하단: 공정 카드별 설비, 시간, 품목 투입·산출·부산물 드롭 대상; 운송 요약
- 우측 검사기: 선택 공정의 담당 설비, 부지/공장, 품목 연결 수, GLB 경로 상태 및 이동 링크
- 도움말: 사용자 입력 순서, 저장 범위, 3D 검증 한계

## 3. 상태·상호작용 규약

| 동작 | 현재 계획 데이터 변경 | 검증 |
|---|---|---|
| 품목을 공정 투입에 놓기 | `process.inputIds` | 마우스 드래그 또는 탭-선택 후 대상 칸 클릭; 중복 ID 미추가 |
| 품목을 공정 산출에 놓기 | `process.outputIds` | 마우스 드래그 또는 탭-선택 후 대상 칸 클릭; 중복 ID 미추가 |
| 품목을 부산물에 놓기 | `process.byproductIds` | 마우스 드래그 또는 탭-선택 후 대상 칸 클릭; 중복 ID 미추가 |
| 설비를 공정 배정 칸에 놓기 | `process.equipmentId` | 마우스 드래그, 탭-선택 후 대상 칸 클릭, 또는 검사기 선택; 계획 설비만 허용 |
| 공정 담당 설비 선택 | `process.equipmentId` | 변경 이력/미저장 표시 |
| 시간축/재생 제어 | 공통 `time`, `speed` | 기존 재생 스케줄 검증 사용 |
| 저장 | 기존 서버 계획 API | 로그인/권한/서버 응답으로만 성공 판정 |

상태는 기존 단일 계획 객체를 공유한다. 새 화면은 iframe, 복제 저장소, 새 3D 컨텍스트를 만들지 않는다. 원본 화면은 덮어쓰지 않으므로 새 URL을 열지 않으면 기존 사용 흐름에 영향이 없다.

## 4. 기존 기능 재사용/비범위

- 재사용: 제품/BOM, 부지/공장/설비 배치, 공정 순서, 입출력 품목, 운송 차량·입출구·경로, 설비 스튜디오/자료, Three.js 씬, 계획 검증, 저장·복원, 도움말/전체 기능 목록.
- 700+ 공통 카탈로그 검색은 스튜디오 페이지가 원본이며 통합 작업대는 해당 검색으로 연결한다. 좌측 팔레트에 700개 전량을 별도 복제하지 않는다.
- 현 렌더러는 USD 원본을 직접 재생하지 않는다. GLB 변환/호환이 필요하다.
- 품목 ID를 공정에 연결하는 UI는 포함하지만, 품목별 개별 GLB의 정확한 공정별 생성·소멸/형상 변형 애니메이션을 새로 구현한 것으로 간주하지 않는다. 현재 작업물은 기존 가상 시연 형상일 수 있다.
- 로그인 서버의 저장-새로고침-재조회는 유효한 사용자 세션으로 별도 확인한다.

## 5. 수용 기준 / QA

1. 새 화면과 기존 6개 탭이 동일 계획 이름/공정/설비 수를 보인다.
2. `iframe` 요소가 0개이고 실제 WebGL canvas가 작업대 안에 연결된다.
3. 품목 드래그→투입/산출/부산물 드롭이 각 해당 ID 배열에 한 번씩 기록된다.
4. 설비 드래그 또는 선택→공정 배정이 해당 `equipmentId`를 갱신한다.
5. 필터와 검색은 현재 계획 팔레트만 좁히며 렌더러를 재초기화하지 않는다.
6. 재생/일시정지와 시간축이 동일 계획의 공정 시간에 반영된다.
7. 기존 제품/배치/공정/스튜디오/실행/검토 탭으로 왕복한다.
8. 잘못된 저장 성공을 표시하지 않는다. 인증되지 않으면 서버 저장 실패/인증 필요 상태를 보여준다.
9. 데스크톱 및 390px 모바일 폭에서 가로 overflow가 생기지 않는지 육안 확인한다.

각 기준의 결과는 배포 후 자동화 QA에 기록한다. 검증되지 않은 모델 동일성·실측·사용권·실물 공정 적합성은 PASS로 집계하지 않는다.

## 6. 변경 및 복구

- 추가 경로: `production-workspace-unified.html` + `production-workspace-unified.js`
- 원래 `production-workspace-front.html`은 변경하지 않는다.
- 원격 대상 경로에 동일 파일이 이미 있으면 배포 스크립트가 `/opt/Resonance/projects/P006/backup/unified-workbench-<timestamp>/`에 먼저 복사한다.
- 롤백은 새 경로의 파일 두 개만 백업본 복구 또는 제거하면 되며 서비스 재시작은 필요하지 않다.
