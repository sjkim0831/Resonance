# 제품·품목에서 부족 설비를 AI로 준비하는 화면·업무 설계

- 작성일: 2026-10-04 (KST)
- 기준 화면: `production-workspace-front.html`의 `#product`, `#process`, `#studio`
- 목표: 제품 구성품·중간품·완제품·부산물 정의를 유지하면서, 공정에 필요한 설비를 발견·조사·검토·계획 등록·공정 배정하고 3D/애니메이션 흐름으로 전달한다.
- 원칙: AI가 실제 자산 원장을 무검토로 수정하거나 임의로 공정에 배정하지 않는다. 미확인 정보는 미확인으로 저장한다.

## 1. 결정 요약

**제품·품목 화면에 자산 원장 전체를 편집하는 설비 양식을 넣지 않는다.** 제품 품목과 설비는 서로 다른 엔터티다. 대신 제품·품목 화면에는 `공정에 필요한 설비 확인` CTA와 진행 요약을 둔다. 이 CTA는 선택 계획을 보존하고 2번 공정 흐름의 설비 요구 단계로 이동한다. 사용자가 공정이 아직 없으면 공정 흐름 화면에서 순서를 구성하도록 안내한다.

정확한 추천 기준은 BOM만으로 만들 수 없다. `제품/산출품 → 공정 단계 → 공정별 작업·능력 요구 → 설비 후보` 순으로 정보를 결합한다. AI 5단계는 기존 설비의 품질 개선·근거 축적에 재사용하고, 신규 설비 후보는 별도의 자산 준비 세션으로 추적한다.

## 2. 사용자가 보게 될 메뉴와 배치

상단 워크스페이스 탭은 기존 순서를 유지한다.

1. `제품·품목`: 제품/BOM/공정 산출품·부산물의 정체성과 3D 품목 모델을 관리한다.
2. `부지·공장·배치`: 배치 공간을 관리한다.
3. `공정·운송`: 생산 순서, 투입/산출/부산물, 설비 요구 및 운송을 관리한다.
4. `설비 스튜디오`: 설비 프로필, 제조사/모델, 근거, AI 제작 5단계, 가동/애니메이션을 관리한다.
5. `실행·3D`: 같은 계획의 품목·설비·운송 결과를 공통 시간축으로 본다.
6. `검토·저장`: 누락·충돌·승인 상태와 저장/복원을 확인한다.

### 2.1 1번 제품·품목 화면에 추가할 요약 카드

`BOM/품목 카탈로그` 아래, `공정에 필요한 설비` 카드를 한 장 추가한다.

- 표시: 공정 수, 설비 요구 슬롯 수, 기존 자산 후보 수, 계획 등록 수, 미해결 요구 수.
- CTA A: `공정 설비 요구 확인` → 공정 탭의 설비 요구 요약으로 이동.
- CTA B: `부족 설비 준비` → 미해결 요구가 있으면 그 요구를 선택한 채 설비 스튜디오의 AI 제작 5단계로 이동.
- 빈 상태: “설비 추천은 공정 순서와 작업 내용을 기준으로 합니다. 먼저 공정을 확인하세요.”
- 경고: 제품의 3D 품목 후보를 설비 자산으로 자동 재사용하지 않는다. 설비와 품목 자산 원장을 UI/타입에서 분리한다.

1번 화면의 역할은 제품/품목 입력, 기존 제품 카탈로그 검색, 중간품·완제품·부산물 구분, 품목 3D 모델 연결, 공정/설비 준비 진행상태를 요약하는 데 한정한다.

### 2.2 2번 공정·운송의 설비 요구 영역

각 공정 카드에 다음 구획을 둔다.

- 제품 흐름: 투입 품목, 산출 품목, 부산물, 수량/단위/수율(미확인 허용).
- 작업 정의: 작업 목적, takt/cycle time(근거 상태와 단위), 선행/병렬 관계.
- 설비 요구: 설비 유형, 처리 능력/용량, 필요한 작업 범위, 인터페이스/치공구, 안전 제약, 필수/선택 여부.
- 설비 충족 상태: 계획 배정 설비, 공통 자산 후보, 요구 충족 정도, 근거 미확인 항목.
- CTA: `기존 자산 검색`, `AI로 부족 설비 조사`, `배정 설비 보기`.
- 운송 흐름: 품목 ID/수량, 운반수단, 출발·도착 공장/부지, 도착 공정.

요구 프로필을 사용자가 모르면 입력 강요 대신 `AI 초안 제안`을 제공한다. 제안은 원본 요구를 덮지 않고 `AI 제안 · 미검토`로 별도 보관한다. 전문가 확인 전에는 검증 완료로 표시하지 않는다.

### 2.3 설비 스튜디오의 AI 5단계 및 신규 후보 상태

기존 설비를 선택하면 기존 자산 ID를 대상으로 실행한다. 신규 설비 후보는 `임시 설비 후보 ID`를 발급해 기존 자산 코드를 임의 복제하지 않는다.

1. 참고자료 수집: 공개 제조사·모델/이미지/도면/매뉴얼/영상 출처와 요약 저장.
2. 3D 시안 5개: 자료 근거/추정 요소/차이점/출처를 시안별로 표시; 모두 제안일 뿐 실물 동일성 아님.
3. USD·GLB 제작: 선택 시안, 치수 근거, 원본/변환 산출물 및 해시를 기록.
4. 가동 정보 수집: 가동부/축/방향/거리/속도/작업 순서와 출처 연결.
5. 애니메이션 제작: 검토된 노드·피벗·축·구간을 사용해 실행 미리보기 생성.

단계별 상태는 `준비 전 → 요청 가능 → 대기 → 실행 중 → 결과 검토 → 승인/반려`로 공통화한다. `구현 예정` 단계를 실행 가능한 것처럼 보이지 않게 한다. 실제 연결 API가 없는 2·3·5 단계는 비활성화 상태와 예상 입력/산출물을 설명한다. 재시도는 이전 작업 ID/멱등 키를 사용하고 자동 중복 청구를 방지한다.

## 4. 데이터 구조 초안

계획 문서 내부에 최소 다음 객체를 추가한다. 기존 `parts`는 제품 흐름 품목으로 보존한다.

```json
{
  "equipmentRequirements": [{
    "id": "req-uuid",
    "processId": "process-id",
    "name": "프레스 성형 설비",
    "equipmentTypeCode": "...",
    "capability": {"force_kN": null, "stroke_mm": null, "bed_mm": null},
    "constraints": [],
    "priority": "required",
    "status": "OPEN",
    "recommendedAssetIds": [],
    "assignedEquipmentId": "",
    "provenance": {"source": "USER_OR_AI", "reviewStatus": "UNREVIEWED"}
  }],
  "equipmentCandidates": [{
    "id": "candidate-uuid",
    "requirementId": "req-uuid",
    "sourceAssetId": null,
    "temporaryEquipmentId": "tmp-eq-uuid",
    "manufacturer": null,
    "model": null,
    "aiJobIds": [],
    "status": "DRAFT",
    "evidenceIds": [],
    "reviewStatus": "UNREVIEWED"
  }]
}
```

- 기존 자산 선택 시 `sourceAssetId`, `current_version_id/version_no/hash`를 고정한다.
- GLB 프리뷰 가능 여부와 USD 보유는 서로 다른 상태로 유지한다.
- `parts[].model`은 품목 모델 경로; `equipment[].glb/usd`는 설비 모델 경로. 서로의 ID를 교차 저장하지 않는다.
- AI가 제안한 제조사·치수·속도는 반드시 필드별 출처 ID와 `CONFIRMED/ESTIMATED/UNKNOWN` 상태를 보유한다.
- 삭제 시 process/equipment/transport/asset version 참조를 검사하고, 사용 중이면 삭제를 막고 연결 해제를 안내한다.

## 5. API 연결 계약 및 현재 준비도

코드베이스의 현재 계약을 기준으로 한다. 배포 대상 서버가 같은 개정인지 먼저 확인해야 한다.

| 계약 | 용도 | 현재 주의 |
|---|---|---|
| `GET /projects/P006/registry-api/assets?q={query}&limit=50&after={cursor}` | 공통 원장에서 기존 설비/자산 검색 | 검색은 100개 상한·커서 페이지. 응답에 제조사/현재 버전/GLB manifest가 일부 포함. 로그인/권한 결과를 명시 |
| `GET /projects/P006/registry-api/assets/{assetId}` 및 자산 버전 조회 | 상세·승인 버전/파일 상태 확인 | UI에 보이는 검색 결과만으로 실물 동등성 단정 금지 |
| `GET/POST /projects/P006/registry-api/ai-authoring/status` 및 `/ai-authoring/{assetCode}` | AI 설비 작업 상태/생성·결과 폴링 | 현재 백엔드 허용 stage는 `references`, `motion`만. Kilo 로그인, 사용자별 범위, 동시 2건/일 20건. 작업은 참고자료에 미검토 결과 저장 |
| `POST /projects/P006/registry-api/assets` | 새 원장 자산 등록 | 관리자 전용. `new_asset_candidate`가 OPEN이어야 하고 실제 USD 경로/검토 메모 등 계약 필요. AI 호출만으로 자동 등록 금지 |
| `POST /projects/P006/registry-api/production-plans/{id}` | 계획의 요구·연결 정보 저장 | 현재 계정별 계획 저장/version 충돌 계약이 있으므로 schema 확장 호환성 확인 필수 |

**API gap:** 작업 큐/폴링 UI를 1번 화면에 노출하기 전, 현재 서버에서 인증 후 실제 사용자 권한으로 상태 GET, job POST, job GET, reference evidence 저장을 재검증한다. 3D 5시안 생성, USD 제작, 애니메이션 생성 API는 현재 AI backend STAGES에 포함되지 않는다. 이 3단계를 허위로 실행 가능 표시하지 않는다.

## 6. 추천 UX 규칙

1. 기존 700여 개 공유 자산 검색을 기본 경로로 제공한다. 기본 검색은 ID/이름/영문명/제조사이며, 범주/파일·버전 상태 필터를 더한다.
2. 서버 페이지네이션과 결과 수를 사용하고, 모든 카탈로그를 DOM에 한 번에 렌더링하지 않는다.
3. 상위 추천 5개에는 추천 근거(유형/용량/업무/공정), 누락 데이터, 실물 확인 수준, 사용 가능 버전을 표시한다. 점수만으로 자동 선정하지 않는다.
4. 필수 능력 미충족은 “추천”이 아니라 “확인 필요”로 표기한다. 용량/행정 값이 부족하면 질문형 보완 패널을 연다.
5. `계획에 추가`는 초안 계획에만 연결한다. `공정에 배정`은 선택 공정·계획 상태를 확인 후 별도 클릭한다.
6. 새 설비 추가 선택 시: `기존 Asset 검색` 우선, `미등록 후보 조사` 다음, `공유 원장 등록 요청` 마지막(관리자/승인 게이트).
7. 진행 상황은 작업 ID/시작·경과시간/최근 이벤트/출처 개수/응답 본문/결과 저장 상태/오류코드로 표시한다. 단계 전환 문자열만 반복해 실시간인 것처럼 보이지 않는다.
8. AI 조사 중 재탐색은 별도 새 요청으로 설명하고 비용/한도 경고를 보여준다. 조사 완료·저장 결과는 `UNREVIEWED`로 표기하고, 출처 중복·삭제 정책을 따른다.

완료 판정은 단위 테스트 수만으로 하지 않는다. 최소 업무 프로세스 1개에서 편집자 입력 → 검색/AI 작업 → 검토 → 계획 저장/복원 → 공정 배정 → 3D 실행까지 실제 계정으로 확인한다. 제조사 동일성/실제 능력/안전 승인은 인간 승인 증거가 있어야 통과한다.

## 8. 구현 우선순위 / 완료 산출물

### P0 — 검색 및 계획 연결 (가장 먼저)

- 1번 요약 CTA + 2번 공정별 설비 요구 + 700여 개 원장 검색·커서 페이지 + 기존 자산 계획 연결.
- 새 후보는 임시 ID로 관리, 실제 원장에 등록하지 않음.
- 계획 schema version/migration 및 old saved plan backward compatibility.

### P1 — AI 5단계의 2개 실제 실행 연결

- 현재 API에서 지원하는 `참고자료 수집`, `가동 정보 수집`에 진행/응답/오류/복원 UI 연결.
- 작업 조회 재접속, idempotency, 등록 출처 수 및 미검토 보고서.
- 로그인/권한 오류를 제품 탭·스튜디오 양쪽에 일관되게 처리.

### P2 — 나머지 3단계 및 카탈로그 승인

- 3D 5시안, USD/GLB 산출, 애니메이션 결과/버전 APIs가 별도로 존재하고 보안·파일 검사를 통과한 뒤 구현.
- 제출→초안 버전→검토→승인→원장 등록/공정 배정으로 승격.
- 산출물은 hash, 단위, 좌표계, 소스 자산/버전, 라이선스, 사용자/승인 이력을 저장.

### 변경할 문서 및 도움말 동기화

- 업무 흐름/화면 설계 및 API/DB 설계 추적표.
- 제품 화면 도움말, 공정 설비 추천 길잡이, 전체 업무 보기 다음 작업 카드.
- 자동 QA checklist와 프로세스 증거 로그.

## 9. 배포/롤백/관측성

- 정적 화면 변경과 서버 API 변경을 분리한다. 먼저 schema/API 호환 검사를 하고, 하위 호환 프론트만 배포한다.
- 기존 배포 HTML/문서를 용량 여유가 충분한 프로젝트 백업 디렉터리에 timestamp로 복사; 사용자 자료와 계획 DB는 삭제/마이그레이션하지 않는다.
- 정적 리소스만 교체 가능한지 확인해 무빌드/무재시작 경로를 우선한다. 롤백은 이전 파일 복원 + URL revision cache bust.
- API 작업 기록에는 계정 식별자를 원문으로 남기지 않는다. 작업 ID, stage, 상태, 시작/경과, 응답 code, source count, persistence status만 최소 로그로 남긴다.
- 속도 예산: typing debounce 250–350ms, API page limit≤100, 사용자 화면 결과 첫 20–50행, 3D 로딩은 가시 뷰포트 우선. 측정 후 조정하며 가정값은 성능 보증이 아니다.

## 10. 지금 할 다음 작업 1개

**P0 검색·계획 연결을 먼저 구현/QA**한다. 사유: 부족 자산을 찾을 수 없는 상태에서 AI 시안/모델/애니메이션으로 가면 결과를 어느 자산·어느 공정에 귀속할지 불명확하다. 검색→선택→계획 초안→공정 배정의 안정성을 먼저 확정한 뒤, P1에서 이미 존재하는 두 AI endpoint와 실시간 상태/응답 패널을 묶는다.

작업할 모델/개발자 지시문은 다음 한 문장으로 시작한다:

> 기존 `production-workspace-front.html` 경로와 하나의 계획 데이터 모델을 유지하면서, 제품·품목 화면에 설비요구 요약/진입 CTA를, 공정 화면에 공정별 설비요구·기존 700+ 공통 자산 검색/선택/계획추가/배정 흐름을 구현하라. 제품 품목과 설비를 혼합하지 말고, 미등록 설비는 임시 후보 ID로 분리하라. 기존 원장은 검색만 가능하게 하고 관리자/후보/승인 게이트를 우회하지 말라. 현재 AI backend에서 실제 활성화된 references/motion만 live job 진행·응답/저장/오류로 연결하고, concepts/USD/animation은 backend contract가 추가되기 전 실행 완료처럼 보이지 않게 하라. 구계획 호환, 계정 권한·401/403/409, 페이지네이션, 중복 요청 방지, 실제 저장/복원/공정 배정/3D 표시, 모바일·키보드 접근성까지 QA하고 screenshot 및 업무로그를 제출하라. UI/도움말/전체업무/QA/화면설계 추적 문서도 동기화하고, 배포 전 백업 및 롤백 파일을 제공하라.

## 11. P0 프론트 구현 업데이트 · 2026-10-04

- 구현 위치: 기존 통합 화면의 `#product` 제품 요약 뒤, `#process` 공정 흐름 뒤. 별도 라우트/iframe은 만들지 않았다.
- 제품 화면은 요구/배정 현황 요약과 공정 설비 화면 이동만 제공한다. BOM 품목과 설비는 별도 목록으로 유지한다.
- 공정 화면은 공정별 요구 정의, 기존 계획 설비 배정, 공통 자산 원장 읽기 전용 검색(50건 커서 페이지), 후보의 계획 추가, 선택 공정 배정을 별도 동작으로 제공한다.
- 계획 데이터에 `equipmentRequirements`, `equipmentCandidates`를 추가하는 확장 방식이다. 기존 키를 교체하지 않으며 계획 API는 제한된 JSON 문서 전체를 저장하므로 구버전 계획도 그대로 읽는다.
- 카탈로그 검색 후보의 자산 ID/버전/seed hash/GLB 상태를 기록한다. 실물 동등성·성능 적합성·안전성·승인은 자동 판정하지 않는다. 자동 배치는 근사 위치이며 충돌이 없고 포락 내 배치되었다고 보증하지 않는다.
- 현재 자동 QA: 도메인 15개 + 생성 HTML 5개 = 20 PASS. 계획 API 테스트에 요구·후보 필드 저장/복원 확인을 추가한다. 인증된 실제 카탈로그 검색·선택→서버 저장/복원은 별도 실브라우저 검증 대상이다.
- AI 5단계 호출은 이 P0에 포함하지 않는다. 기존 API가 지원하지 않는 시안 5개·USD 제작·애니메이션 단계를 실제 실행으로 표시하지 않는다.
- 다음 원씽: 로그인된 사용자 세션에서 카탈로그 검색 50건/다음 페이지 → 후보 계획 추가·공정 배정 → 서버 저장/새로고침 복원 1건을 검증한다. 그다음 AI references/motion 단계의 작업 이벤트 UI를 연결한다.
