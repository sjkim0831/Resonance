# P006 공장 성능·LOD 설계·검증 카드

현재 UI 변경: 사용자 요청으로 통합 `공장 성능·LOD` 진입 버튼과 팝업 생성 스크립트 연결을 제거했다. 메인 초기 로딩 결과는 유지한다. 아래 통합 창 관련 기록은 이전 구현 이력이다. 다음 화면 설계 후보는 편집기 하단 한 줄 요약 + 캔버스를 줄여서 여는 하단 결과 패널이며, 아직 적용하지 않았다.

## 사용 순서

### 메인 화면 초기 로딩 결과

Composer 상태줄과 배치 편집기 사이에 `공장 규모별 초기 로딩 시간 측정 결과`를 상시 표시한다. 현재 공장 및 100/300/700개 설비 행에서 동일 저장 버전의 최신 원본 모델 측정 이력을 조회한다. 최초 화면, 초기 준비, 조작 준비의 중앙값과 최소/최대를 표시하며 모든 회차 상태와 캐시 조건은 상세 영역에 보존한다. 미측정·대상 없음·HTTP 조회 오류를 구분한다. `현재 공장 로딩 측정 · 5회`는 별도 보이는 iframe에서 저장본을 5회 로딩하며 FPS 측정은 수행하지 않는다. 결과는 기존 benchmarks API에 `scenario=LOAD_ONLY`로 저장한다. 표시되는 규모별 값은 환경·화면·캐시가 다를 수 있어 직접 개선율로 해석하지 않는다.

실제 QA(2026-09-23): 외부 IP의 ebd63f43-0146-4173-9a66-ab09b67a438c/v2/3설비에서 5/5 PASS. 첫 Geometry 중앙값217.4ms, 초기 준비228.3ms, 조작 준비233.6ms, 조작 준비 최소224.3ms/최대332.5ms. 서버의 Headless Chromium/SwiftShader 측정이다. 저장·새로고침 결과 동일, 편집 문서 동일을 확인하고 메인 화면 스크린샷을 남겼다. 일반 HTTP 주소에서는 crypto.randomUUID가 없을 수 있어 측정 ID를 crypto.getRandomValues 기반 UUID v4로 생성하도록 통합 측정 화면도 수정했다. 다음 업무는 실제 사용자 브라우저에서 같은 버튼으로 재측정하고 캐시/렌더러 조건을 비교하는 것이다.

접기/펼치기 QA: 요약/상세 패널 접기, 펼치기, 새로고침 후 상태 유지 3항목 PASS. 상태는 같은 브라우저 탭에서 레이아웃별로 저장한다.

2026-09-23 화면 진입 보완: `DB 저장` 옆에 `공장 성능·LOD` 링크를 HTML에 직접 등록했다. 클릭하면 Composer 내부 대화상자에서 측정 화면을 열고 현재 layoutId를 자동 선택한다. 닫기/Escape는 편집 문서를 보존한다. 측정 중 닫기는 취소 요청을 전달한다. URL `ebd63f43-0146-4173-9a66-ab09b67a438c`의 실제 외부 IP 화면에서 버튼 표시, 대화상자 진입, 현재 공장 선택, 닫기, 문서 불변 5항목을 확인했다. 재발 예방: 진입 버튼은 E001 LOD 초기화의 성공 여부에 의존하지 않는다. 다음 업무 카드: 기존에 열어둔 브라우저는 미저장 작업을 저장한 뒤 새로고침하여 새 진입점을 사용한다.

Factory Composer 상단의 **공장 성능·LOD** → 저장 공장 선택 → 반복 수·시간·카메라 시나리오·LOD 설정 → 측정 시작 → 결과 및 저장 이력 확인 → JSON/CSV 내려받기. 새 화면이 실제 Composer를 표시하며 기존 편집 창은 그대로 둔다. 기본 반복 5회, 준비 5초, FPS 측정 30초다. 기본 설정의 전체 실행 시간은 5 × (로딩 시간 + 35초) 이상이다.

## 계측과 데이터

| 요구 | 코드 | 결과 |
|---|---|---|
| 저장 공장·규모 선택 | `composer_api.py /layouts`, `factory-performance.js` | 설비/건축 수, 100/300/700 대상 상태 |
| 실제 3D 초기 로딩 | `factory-performance-probe.js` + Composer `GLTFLoader` | DB 조회 종료, GLB ResourceTiming, 파싱 callback, 첫 Geometry 렌더, 초기 모델 준비, 조작 handler 준비 |
| FPS/프레임 | iframe 내부 `requestAnimationFrame` + 실제 WebGL renderer | 프레임 간격 중앙/P95/P99, 평균 FPS, 렌더 CPU, Draw Call, Triangle |
| LOD | `factory-lod.js`, E001 별도 GLB 2종 | 원본/강제 단계/자동, 선택 원본 유지, 거리 전환 이력 |
| 이력 | `p006_factory_benchmark` | 관리자 권한, 공장 버전 일치 검사, 원시 회차·실패 저장 |

타이밍은 페이지 navigation 시작 후 경과한 시각이다. DB 조회와 다운로드·파싱·렌더가 겹치므로 합산하지 않는다. `modelParseMs`는 GLTFLoader parse callback까지의 호출 시간 합이며 병렬 실행 시 벽시계 시간과 다를 수 있다. `firstGeometryMs`는 3D 장면에 Mesh가 실제로 들어간 뒤 렌더 함수가 끝난 첫 시각이다. `initialReadyMs`는 초기 대상 자산의 GLB 처리 완료 후 렌더 시각이다. 조작 준비는 카메라·선택 이벤트 handler, WebGL canvas 크기, 초기 렌더가 확인된 시각이다. 실제 사용자 입력의 응답 지연은 별도 수동/자동 조작 검증이 필요하다.

브라우저 Resource Timing의 `transferSize=0`은 다운로드 0바이트를 뜻하지 않는다. 모든 GLB 요청에 브라우저 `deliveryType=cache`가 기록된 회차만 `WARM_OBSERVED`, 그 외에는 `CACHE_UNKNOWN`으로 둔다. 캐시를 강제로 비우지 않았으므로 `COLD_VERIFIED` 결과는 없다. 비교 화면은 레이아웃 버전·화면 크기·캐시 등 측정 조건이 다른 회차를 직접 개선율 계산에서 제외한다. 브라우저 탭 비활성화 여부를 각 FPS 실행에 기록한다. GPU 프레임 시간, 주사율, Omniverse 로딩은 측정 연결 전까지 미측정이다. 수직 동기화 영향 때문에 FPS를 GPU 여유 성능으로 해석하지 않는다.

## LOD Pilot

대상은 E001 한 종이다. 원본 GLB의 SHA-256은 `4f450810d8b0ad638f5005175f895337abf7302ec360329abb57deac3d888024`이다. 별도 파일 두 종을 `gltf-transform simplify 4.5.0`으로 생성했다. 원본/LOD1/LOD2의 삼각형은 6,587/5,101/4,466개, 크기는 5,639,388/5,586,836/5,563,628바이트다. Node 16개, Mesh 6개, 재질 2개, 텍스처 6개, Node 계층·Transform과 실제 Scene Bounds는 같았다. 원본에는 임베디드 animation clip이 0개이므로 가동부 애니메이션 보존은 **미검증**이다. 별도 계약 기반 움직임, 선택, Port와 충돌 판정은 원본 기반이며 LOD를 근거 승격에 사용하지 않는다.

자동 표시 전환은 원본→LOD1 20m, 역방향 16m, LOD1→LOD2 40m, 역방향 34m의 Pilot 기준이다. 제조사 수치가 아니다. 선택된 E001은 원본으로 표시한다. 다른 자산은 원본으로 유지하며 화면은 E001 Pilot만 지원한다고 알린다. 단계가 바뀔 때 파일 로드가 필요하면 그 기간의 로딩 시간을 별도 표시한다.

## 품질·안전 Gate

PASS는 저장 공장 버전 일치, WebGL 렌더 성공, 초기 대상 모델 누락 0, fallback 0, 보이는 탭에서 FPS 측정 완료일 때만 기록한다. TIMEOUT, CANCELLED, PARTIAL과 오류도 DB에 남긴다. 대체 형상, 애니메이션 부재, 전송 바이트 미확인은 결과에 그대로 기록한다. QA용 반복 레이아웃은 이름에 `PERF` 또는 `SYNTHETIC`을 붙여 실제 공장과 구분한다.

## QA·화면 설계·다음 업무

페이지·액터·기능·입력·출력 검증 순서는: 관리자 로그인 → 저장 공장 선택 → 3D 로딩 → 1회 짧은 측정 → 이력 저장 → 새로고침 → 복원 → CSV/JSON 확인이다. 실패 사례는 3D 미지원 브라우저, 누락 GLB, 타임아웃·취소, 비활성 탭을 일반 측정과 구분해서 검사한다. 계측 오버헤드는 동일 공장/브라우저에서 probe 활성·비활성 회차를 비교해야 수치화할 수 있다.

## 2026-09-23 실제 검증 결과와 제한

- 관리자 계정/페이지/기능/입력/출력: 저장된 3설비+6건축 객체 Pilot을 선택해 원본·LOD1·LOD2 표시를 각각 실제 WebGL에서 확인했다. DB에 집계 및 개별 회차가 저장되고 새로고침 후 이력이 복원됐다. 초기 타임아웃 2건도 이력에서 숨기지 않았다.
- 3설비 원본 5회 반복(준비 0초·FPS 1초의 기능 시험): 조작 준비 중앙값 406.5ms, 최소 384.3ms, 최대 492.1ms, 평균 FPS 중앙값 44.0. 기본 5초+30초 장기 측정 완료를 뜻하지 않는다.
- 100설비 QA 사본의 2초 단발 측정: 원본 1.011FPS/1,340,648 Triangle/1,356 Draw Call, LOD1 0.609FPS/1,313,900 Triangle, 자동(LOD2 표시) 1.118FPS/1,302,470 Triangle. 소프트웨어 WebGL(SwiftShader)의 극단적 저FPS와 회차 1회라는 한계가 있으므로 성능 개선을 확정하지 않는다. 원본보다 악화된 LOD1 결과도 그대로 기록한다.
- GLB 하나를 차단한 실패 시험은 `PARTIAL`, 2/3 로드, `GLB_LOAD_ERROR`로 저장했다. 측정 취소는 `CANCELLED`로 저장했다. 애니메이션 없는 공장의 애니메이션 FPS는 `ANIMATION_NOT_AVAILABLE`로 남겼다.
- 캐시 관찰 시험 2회는 첫 회 `CACHE_UNKNOWN`, 다음 회 `WARM_OBSERVED`였다. 브라우저 캐시 강제 비움과 GPU 시간은 미검증이다.
- 자동 LOD의 선택 유지 시험: 카메라 거리 34.35m에서 E001은 LOD1이었다. E001 Instance를 선택한 뒤 비동기 로딩이 끝나자 표시 경로가 원본 `E001.glb`로 돌아왔고 선택 1개가 유지됐다.
- 실제 2D·3D 화면 및 6초/15FPS/90프레임 카메라·LOD 전환 영상을 남겼다. 영상은 설비 기계 애니메이션 증거가 아니다. 대표 Pilot E001에 임베디드 클립이 없으므로 그 항목은 미검증이다.
- 저장된 100설비 QA 사본은 있으나 300·700설비 저장 레이아웃은 현재 목록에 없다. UI에 `측정 대상 없음`으로 표시한다. 100대 테스트는 100개 실공정 검증이 아니다.
- DB `p006_factory_benchmark`는 현재 16행/131,072바이트, 추가 LOD 파일 두 개는 11,150,464바이트다. 외부 유료 API는 사용하지 않았다. GPU·전력·인건비 단가는 제공되지 않아 금전 비용은 산정 불가다.

다음 업무 카드: 실제 GPU가 있는 화면에서 동일 카메라·캐시 조건으로 기본 5회×35초를 재측정하고, 100대의 1,356 Draw Call 병목을 우선 확인한다. 300/700대는 분리된 테스트 레이아웃을 저장한 뒤에만 측정한다. E001의 실제 가동부 계약 검증 전에는 LOD의 애니메이션 보존을 PASS로 올리지 않는다. LOD 확대도 자산별 Node·Pivot 보존 검증을 통과한 종에만 진행한다.

## `P006-LOD-OPTIMIZATION-RESULTS` 화면 반영

- Composer 하단 `공장 성능 결과` 펼침 패널에 `LOD 적용 결과 · 단계별 모델 최적화`를 추가했다. 별도 팝업은 없다. 패널은 접기/펼치기를 유지하고 펼쳐진 상태에서는 최대 높이 75vh 안에서 스크롤한다.
- 단계 선택은 상단 LOD selector와 하단 결과의 `원본 / LOD1 / LOD2 / 자동` 선택을 같은 `P006_LOD` controller로 연결한다. 모델 준비 중에는 기존 Geometry를 계속 보이는 상태로 표기하며, 현재 레이아웃의 E001 Instance가 없으면 그 사실을 표시한다.
- 하단 표는 배포된 `factory-lod-manifest.json`에서 파일 경로·용량·용량 감소율·Mesh·Node·Vertex·Triangle·Triangle 감소율·Material·Texture·SHA·생성 설정을 불러온다. 현재 E001 1종만 지원하며, 미지원 Asset은 지원 수/전체 고유 Asset 수로 분리한다.
- 3D Scene이 준비되면 현재 Renderer의 Triangle·Draw Call 총계를 별도로 표시하고 JSON에 포함한다. 이는 E001 단독 통계가 아니라 전체 장면 통계이며, 장면이 준비되지 않으면 미측정이다.
- 현재 저장 레이아웃 버전의 기존 Benchmark 이력에서 LOD mode별 첫 Geometry·조작 준비·FPS·Frame P95·Triangle·Draw Call을 표시한다. 저장 이력이 없으면 `미측정`; 조건이 다른 모드는 비교 개선율을 계산하지 않는다. 이 화면 추가 자체는 새 Benchmark 레코드를 만들거나 DB를 변경하지 않는다.
- `LOD 결과 JSON`에는 현재 표시 상태·매니페스트·레이아웃 버전·해당 버전 성능 이력을 포함한다. `LOD 결과 CSV`는 모델 단계별 정적 자산 수치를 내보낸다.
- 한계: E001 원본 파일 크기 대비 LOD1 약 0.93%, LOD2 약 1.34% 감소이며 Triangle은 각각 약 22.6%, 32.2% 감소다. 원본 임베디드 animation clip이 없어 애니메이션 보존은 미검증이다. Node 계층/Transform 보존은 매니페스트 기록으로만 표시하며 이 변경의 런타임 시각 QA로 간주하지 않는다.
- 범위: E001 이외 Asset의 LOD 생성·최적화, GPU 메모리 직접 측정, Omniverse 측정은 미구현/미측정이다. 렌더링용 LOD는 원본 충돌 Geometry·Port/관계 Evidence를 변경하지 않는다.
