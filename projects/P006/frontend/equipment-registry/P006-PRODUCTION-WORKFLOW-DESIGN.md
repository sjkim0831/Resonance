## 2026-09-25 6단계 생산 설계 흐름

- 제품 선택 → 사용자 정의 부지 설정 → 저장 공장 참조 추가 → 해당 공장의 실제 Instance를 설비 세트로 선택 → 세트 안에서 공정 순서 작성 → 준비 조건을 확인하고 Factory Composer 3D 작업물 경로 미리보기로 이동한다.
- 단계별로 나누어 입력하되 임시/설계 데이터는 기존 `settings.networkDesign.product.workflow`에 저장한다. `equipmentSet[]`에는 선택한 실제 Instance ID를 기록하며, 공정 순서는 `processSequence[]`로 별도 유지한다. 생산 설계 수정은 공장 Layout의 Asset/Transform/관계 원장을 변경하지 않는다.

- 재생 진입은 제품·부지 입력, 같은 공장 참조와 버전 일치, 설비 세트 포함, 지원 Anchor(E001/E034/E053), 두 개 이상 공정 Instance 조건을 검사한다. 실패 사유를 화면에 열거한다. 성공 시 3D 화면 좌측 하단 ▶을 누르면 기존 경로 재생을 시작한다.

## 2026-09-25 UI 단순화 및 설비 순서 편집

- 화면 흐름을 `제품 → 부지·공장 → 공정·재생` 3단계로 재구성했다. 기존 7단계 긴 텍스트 입력을 공장 안의 저장된 설비 Instance 선택과 순서 조정으로 대체했다.
- 설비 목록은 각 참조 Factory Layout의 실제 `instances[]`에서 Asset ID와 Instance ID가 있는 항목만 사용한다. 빈 응답/참조 오류는 가짜 목록 대신 빈 상태 안내로 표시한다.
- 순서 항목은 `processSequence[]`에 저장하고 화면의 위/아래 버튼으로 조정한다. 공장 내부 배치·Asset·관계 원장은 이 편집만으로 변경되지 않는다.
- 단계 1은 제품/BOM/생산 수량, 단계 2는 부지 설계 치수와 저장된 공장 참조, 단계 3은 실제 Instance 순서와 기존 실행 상태로 구성했다. 제품 후보 목록과 기존 3공장 기능 시연은 보조 `details` 영역으로 접었다.
- 기존 실행 Gate는 유지한다. 설비 순서가 만들어져도 물리 관계 승인, 작업물 전달, 설비 애니메이션 검증으로 승격하지 않는다. 실제 저장/새로고침 성공 여부는 인증 세션으로 검증해야 하며, 이 변경 사항 자체는 해당 검증을 주장하지 않는다.
- 데이터 호환: 기존 `workflow` 필드는 같은 생산망 문서 안에서 보존하고 `processSequence`를 추가한다. 화면의 순서를 설명하는 레거시 `sequence` 텍스트도 파생 저장하여 기존 제품 카탈로그의 `processDescription` 입력 경로와 호환한다.
- QA 상태: 코드 정적 검토 후 배포된 화면의 실제 브라우저 표시/입력 검증을 기록한다. 인증되지 않은 API의 401/실패는 DB 저장 결과로 대체하지 않는다.
- 다음 업무 카드: 제품·공정의 승인된 관계를 연결하고, 각 Instance의 Port/거치 높이/가동부 Evidence가 확인된 뒤에만 실제 작업물 Flow와 연속 애니메이션 Gate를 연다.
- 화면 검수에서 공장이 없을 때 설비 순서 빈 상태가 세로로 찌그러지는 문제를 발견해 표시를 수정했다. 인증 상태는 `P006 로그인 필요`였으므로 저장·복원·실제 참조 Instance 표시 검증은 수행하지 않았다.
- 생산망 문서가 아직 없는 첫 진입에서도 입력을 버리지 않도록 `임시 저장`은 브라우저의 network ID별 draft에 보관하고, 저장된 공장이 연결된 경우에만 `생산망 저장`으로 DB 저장을 시도하도록 구분했다. 임시 저장은 서버 저장을 뜻하지 않는다.

## 2026-09-25 단일 공장 공정 3D 미리보기 (FUNCTIONAL_DEMO)

- 단계 3의 설비 순서 아래에 `선택 공정 3D 미리보기`를 추가한다. 같은 저장 공장 참조에서 2개 이상의 실제 Instance를 지정한 순서대로 사용하며, 참조 Layout ID·버전과 각 Instance/Asset ID를 시작 전에 다시 검증한다.
- 미리보기 Anchor 등록 대상은 현재 Composer의 기존 `PROCESS_ANCHORS`인 E034/E001/E053에 한정한다. 미등록 자산, 공장 간 시퀀스, 참조 버전 불일치 또는 저장 Instance 불일치는 사유를 표시하고 차단한다.
- 생산망과 Composer 사이는 무작위 데이터/쿼리 문자열 상태값이 아니라 브라우저 `localStorage`의 일회성 token을 통해 schema version, network/layout ID와 버전, 선택한 순서, 제품 후보명을 전달한다. Composer는 실제 Layout API 응답과 Instance를 대조한 뒤 token payload를 사용한다.
- Composer에는 저장되지 않는 `processPreviewOnly` 주황색 proxy workpiece를 메모리에서만 추가한다. 재생은 기존 Scene의 실제 설비 GLB를 배경으로 경로 확인용 proxy를 Input/가공부 높이 후보/바닥/다음 설비 접근점 사이에서 이동시킨다. Preview Mode에서 FunctionalSimulation의 제품 처리 완료 이벤트는 호출하지 않는다.
- 화면은 `FUNCTIONAL_DEMO`, 제품 형상 대리, 높이/공정/연결/설비 기계 애니메이션 미검증 상태를 상시 표시한다. 미리보기 작업물은 JSON/DB 저장에서 제외하고, 저장·열기·편집·키보드 변경 명령은 읽기 전용으로 잠근다. 카메라 orbit/pan/zoom과 재생/일시정지/중지는 허용한다.
- 작업물 경로는 별도 `p006-process-preview-core.js`의 순수 기하 함수로 계산한다. 첫 설비 진입 전에 외곽 여유점에서 상승하고, 설비 사이에는 바닥 주행 후 다음 설비 외곽 이전에 상승하도록 한다. 회전된 설비는 local forward/offset을 배치 yaw로 변환한다. 미등록 Anchor/위치/두 설비 미만 입력은 fail-closed 한다. 높이값은 현재 Anchor 후보이므로 실제 접촉·작업물 통과 근거로 사용하지 않는다.
- 경로는 종료점에서 한 번 정지하고, 완료 후 재생은 처음부터 시작한다. 일시정지는 현재 진행률을 유지하며 중지는 시작점으로 복귀한다.
- 일반 Composer에서 순서/작업물 경로가 없는데 재생 상태만 바뀌던 무반응 원인을 수정한다. 이제 경로가 없으면 `BLOCKED`와 함께 이유 및 생산망 공정 순서 설정 링크를 보여주고, 재생 루프를 시작하지 않는다. 미리보기 1회 재생 완료도 조작 상태에 표시한다.
- 회귀 검증 `node p006-process-preview-core.test.js`: 23 assertion PASS (입력 gate, 외곽 이전 상승, 바닥 구간, yaw 변환, 시작·종료 샘플링, 재생 차단 조건 포함). 이는 경로 계산 단위 시험이며 실제 브라우저/DB E2E를 의미하지 않는다.
- 통과로 볼 수 있는 범위: 화면 연결·실제 설비 Instance 조회 후 경로 렌더·작업물 proxy 이동. Direct Connection, 실제 제품 제조/조립, 정확한 거치 높이, 가동부 애니메이션, 인증 DB 저장·복원, Omniverse/USD 동작은 이 미리보기로 검증되지 않는다.
- QA 상태: 생산망 브라우저 실제 표시에서 `P006 로그인 필요`와 빈 생산망 참조를 확인했다. 따라서 인증 데이터와 실제 3D 세트 E2E는 미실행이며 이를 성공으로 표시하지 않는다. 코드 변경 전후 실제 브라우저 통합 확인 및 배포는 별도 결과로 기록한다.
