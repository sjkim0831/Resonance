설비 모델과 설치 배치를 분리하는 통합 설계

원씽: 같은 설비의 위치를 두 번 입력하지 않습니다. 배치 정보는 생산 계획의 배치 인스턴스에서 관리하고, 스튜디오는 모델 제작과 품질 개선을 담당합니다.

1. 원본 코드 대조 결과

현재 위치확인한 구조문제
설비 스튜디오설비 레코드의 installation JSON. 수정 GLB 적용 시 equipmentInstanceId와 equipmentInstallation을 공정 equipmentModel에 복사카탈로그 모델과 설치된 개체를 명확히 구분하는 UI가 부족함
생산 계획 / 실행공정 cellId → 셀 x,z,yaw → 구역 x,z → 공장 위치현재 integrated 렌더링 경로는 equipmentInstallation 대신 셀 좌표를 사용
공장 목록factory.layoutId 선택값 존재선택값만으로 Composer 배치가 실행에 동기화된다고 단정할 수 없음

2. 기존 4개 탭을 유지하는 배치

화면담당 기능
① 제품·부품생산할 제품과 부품 구성. 제조 설비 위치 입력은 두지 않음
② 부지·공장전체 생산망에서 부지 위치·방향·크기 → 부지 선택 시 공장 위치·방향·크기 → 공장 선택 시 설비 배치 목록과 2D/3D 편집. 옥외 설비는 부지 직속 배치
③ 공정·운송공정에 이미 배치된 설비를 선택. 순서·시간·입출력·운반 수단·경로·거리·시간 관리
④ 실행공통 장면과 공통 시간으로 전체/부지/공장 카메라 재생. 선택 설비의 배치 편집과 스튜디오로 이동
설비 스튜디오제조사·모델·자료·썸네일·USD/GLB·가동부·애니메이션 관리. 현재 설치 위치는 읽기 전용 요약과 배치 편집 링크

3. 단일 데이터 기준 — 신규 제안

모델 → 배치 인스턴스 → 공정 참조. 같은 모델을 3곳에 설치하면 모델은 1개, 배치 ID는 3개입니다. 기존 등록 설비 ID는 별도 연결하여 보존합니다.

  • 모델: assetId, 제조사/모델, 버전, GLB/USD, 원점·단위, 가동부 정의
  • 배치: placementId, assetId, equipmentInstanceId(선택), parentType(site/factory), parentId, positionM(x,y,z), rotationDeg(x,y,z)
  • 공정: equipmentPlacementIds. 구역/셀은 선택적 그룹과 자원 점유 규칙으로 유지
  • 좌표: 부지는 생산망 기준, 공장은 부지 기준, 설비는 선택한 부모 기준. 부모 회전과 이동을 자식에 합성
  • 운송: 출발·도착 배치/입출고 지점, 경로, 거리 자동/수동, 속도, 상하차 시간. 수동값을 재계산으로 덮어쓰지 않음

4. 보존·이관 절차

  1. 기존 계획 revision과 JSON 백업. 원본 덮어쓰기 금지
  2. 기존 셀 좌표로 현재 보이는 위치를 먼저 보존. installation 값과 다르면 충돌 목록에서 선택하고 무음 덮어쓰기 금지
  3. Composer layoutId의 객체 ID·좌표 단위·원점을 별도 대조한 후 변환 어댑터 연결
  4. 모델 파일이 같다는 이유로 배치 인스턴스를 합치지 않음. 공유 설비는 명시적 동일 placementId로만 연결
  5. 검증 후 새 revision 저장. 실패 시 이전 revision 복원. 스튜디오 수정은 선택한 배치의 모델 버전만 교체

5. QA · 도움말 · 전체 업무

설계 → 배치 → 공정 연결 → 운송 설정 → 실행 → 모델 개선 → 재실행 순서로 검증합니다.

  • 편집 권한 계정: 동일 모델 3개 배치 → 3개 개별 위치 유지 → 저장/재접속 후 비교
  • 실행 계정: 부지 방향 변경 → 공장·설비 함께 변환 → 전체/개별 카메라에서 동일 위치 확인
  • 공정 공유 설비: 2개 공정의 자원 충돌/대기 계산과 완료 위치 확인
  • 스튜디오: 한 배치의 모델 수정 → 다른 배치 무변경 확인
  • 부지/공장 추가·삭제·옥외 설비·고아 참조·권한 거부·복원 검증
  • 실측 전 크기는 추정으로 표시. 현재 3D의 최대 치수 4 기준 정규화는 실제 크기 배치와 별도로 교체해야 함

현재 검증 범위: 서버 소스 대조. 로그인 저장·이관·재생 E2E는 아직 미실행이며, 이 문서는 구현 완료 보고가 아닙니다.

6. 지금 해야 할 다음 작업

배치 schema와 기존 데이터 변환·충돌 보고 자동 테스트부터 구현합니다. 그 후 ② 탭에 배치 편집을 연결하고 ③·④·스튜디오를 같은 ID로 연결합니다. 추가 입력 필요: 좌표 원점, 실제/대략 치수, 기존 installation 충돌 시 우선값, 공유 설비 여부. 미확인값은 추정/미확인으로 남깁니다.

추가 유료 API 호출: 0회. 구현 시간·운영비는 Composer 데이터와 인증 저장 경로 확인 후 산정합니다.
