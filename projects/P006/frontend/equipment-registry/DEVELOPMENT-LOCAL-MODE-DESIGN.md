# P006 로그인 없는 개발 모드 설계

## 1. 목적 / 범위

개발자가 로그인 세션 없이 기존 계획의 공정 설비 요구를 편집하고, 현재 계획에 이미 포함된 설비를 검색·선택·공정 배정하여 화면과 계획 흐름을 시험할 수 있게 한다. 권한 확인을 없애거나 공유 카탈로그·사용자 데이터를 익명으로 노출하는 것은 아니다.

## 2. 액터·화면·행동

| 액터 | 위치 | 가능 작업 | 저장 범위 |
| --- | --- | --- | --- |
| 비로그인 개발자 | 제품·품목 / 공정·운송 | 계획 편집, 설비 요구 입력, 현재 계획 내 설비 검색, 기존 계획 설비를 공정에 배정, 브라우저 초안 저장 | 현재 브라우저의 localStorage |
| 로그인 사용자 | 동일 화면 | 위 기능 + 공용 자산 원장 검색/추가 후보, 계정 계획 목록/복원/저장 | 계정 서버 |

## 3. 데이터/API 경계

- 로그인 세션 식별 쿠키가 없으면 페이지 시작부터 로컬 모드로 둔다. 익명 시작 시 계정 계획 목록 조회도 억제하며, 인증 상태를 서버 데이터/권한 없이 임의로 만들지 않는다.
- `LOCAL DEVELOPMENT` 후보는 활성 계획의 `p.equipment[]`에서만 생성한다. 후보에 `_localDevOnly`, `_localPlanEquipmentId`, `LOCAL_SAMPLE` 표식을 유지하고 제조사·모델·GLB는 계획 안의 표시값만 보여준다.
- 로컬 검색은 브라우저 메모리에서 수행하며 `/assets`, `/production-plans`, 자료 업로드 또는 AI 제작 API를 호출하지 않는다.
- 로컬 후보는 새 원장 자산을 만들지 않는다. 기존 계획의 설비 ID를 해당 공정에 연결하고 설비 적합성 상태는 `ASSIGNED_UNVERIFIED`로 유지한다.
- 공유 원장 검색과 서버 계획 GET/POST는 기존 로그인·계정 권한 요구를 유지한다. 로컬 개발 모드에서는 서버 계획 버튼/선택을 비활성화하고 함수 호출도 가드한다.
- 플랜 편집은 기존 브라우저 초안 저장 동작을 그대로 사용한다. 명시적 브라우저 저장 전에는 미저장 상태임을 유지하며, 로컬 데이터는 다른 브라우저/기기와 공유하지 않는다.

## 4. 완료 및 QA 기준

1. 익명 페이지에서 페이지 자체를 로그인 없이 열고 공정별 설비 검색 패널을 연다. 시작 상태가 로컬 전용이며, 필요하면 체크박스로 모드를 전환한다.
2. 현재 계획에 존재하는 설비만 검색 결과로 나오며, 임의/가짜 카탈로그 후보가 생성되지 않는다.
3. 설비 선택 후 공정 배정 시 같은 계획의 설비 ID가 공정에 연결되고 미검토 상태로 표시된다.
4. localStorage 계획 저장 후 새로고침하면 변경이 이 브라우저에서 복구된다.
5. 익명 시작과 로컬 모드에서 `/assets`, `/production-plans` 및 AI 요청이 발생하지 않고 서버 계획 버튼도 동작하지 않는다.
6. 로컬 모드를 끄고 로그인한 경우 기존 공용 원장·계정 서버 동작이 유지된다.
7. 좁은 화면에서도 로컬 전용 경고와 전환 컨트롤이 줄바꿈되며 가로 넘침이 없다.

## 5. 비목표 / 주의

- 전체 카탈로그 700여 개 검색, 새 자산 원장 등록, 서버/다기기 저장, 참고자료 첨부, AI 조사/모델 생성/애니메이션 제작은 로그인 모드의 영역이다.
- `localStorage`는 개인 브라우저 개발 편의를 위한 저장소이지 접근제어·백업·감사 로그가 아니다. 운영 데이터의 진실 원장으로 사용하지 않는다.
- 후보의 3D 경로나 텍스트는 표시 및 화면검토에 한정하며 실제 제조사 일치/치수/공정 적합성/안전을 보증하지 않는다.
