# Product Planner 실행 탭 통합 화면

## 목적
기존 4개 탭(제품·부품, 부지·공장, 공정·운송, 실행)을 유지한다. 실행 탭은 `production-scene.html`의 실제 연결 GLB, 공장·부지 배치, 운송 시연을 기본 화면으로 사용한다. 부지 전체 카메라와 부지 안의 공장별 독립 카메라를 메인 3D 바로 아래에 함께 제공하고, E096 Pilot·구형 3D와 셀 시연만 접힌 상세 검토에 둔다. 시간표와 공정별 설비·작업물 연결표도 실행 화면에 남긴다.

## 데이터 흐름
- 제품 계획 편집기는 브라우저 저장소 `p006-product-plans-v1`의 활성 계획을 갱신한다.
- 실행 엔진은 `p006-product-planner-run-v1` BroadcastChannel로 planId, planRevision, 시간, 재생 상태, 배속을 발행한다.
- 실행 탭의 현장 3D는 별도 iframe이 아니라 Product Planner 문서 안에 직접 마운트한다. Shadow DOM으로 ID·스타일을 격리하며 기존 Three.js 렌더러와 GLB 장면을 재사용한다.
- 부모 화면의 재생·일시정지·초기화·배속 조작이 기준이다. iframe은 받은 시간으로 화면만 갱신한다.
- `전체 생산망`과 `부지별 동시 보기`는 같은 Three.js 장면, 연결된 GLB, 제품·운송 상태를 공유한다. 부지별 카메라는 한 렌더러에서 뷰포트만 나눠 그린다. 부지를 추가하면 뷰도 자동으로 늘어난다.
- 각 부지 뷰는 드래그 회전, Alt+드래그 이동, 휠 확대를 독립적으로 처리한다. 이동 중 부품과 트럭은 출발지·도착지 부지 양쪽에서 확인할 수 있다.
- 부지별 독립 카메라 카드는 해당 부지의 설비·작업물을, 공장별 독립 카드는 해당 공장의 설비·작업물을 필터링한다. 각 카드의 세 가지 표시 모드와 카메라 조작 상태는 서로 독립적이다.
- 전체 애니메이션 시작 시 이미 준비한 공통 장면을 사용하고, 기존 재생 시간 변경에 따라 작업물·상태를 갱신한다. 별도 카메라 카드가 실행 탭에서 보이도록 기본 영역에 배치한다.

## 사용 순서
1. 제품·부품과 부지·공장을 입력한다.
2. 공정·운송에서 순서, 시간, 설비 연결을 설정한다.
3. 실행 탭에서 전체 생산망과 아래의 부지·공장별 독립 카메라를 확인한다.
4. ‘전체 공정 애니메이션 재생’을 누르면 공통 재생을 시작한다. 부지·공장 카메라는 같은 모델을 공유하며 추가 다운로드하지 않는다.
5. 각 카메라에서 설비만, 설비와 작업물, 작업물만 보기와 개별 회전·이동·확대를 조작한다.
6. 시간표와 공정별 연결표를 검토하고, 과거 Pilot 화면은 필요할 때 상세 검토를 펼친다.

## 검증 경계
- 브라우저 내 동일 출처 저장 계획과 BroadcastChannel 동기화만 사용한다. 서버 간 협업 동기화는 별도 범위다.
- 재생 시간과 시각화 상태 연동은 실제 생산 물리, BOM 적합성, 설비 동작을 검증하지 않는다.
- 로컬 저장 계획이 없거나 실행 시간표 오류가 있으면 화면에 준비 상태/오류를 표시한다.
- 설비 원본 USD와 웹 표시 GLB는 서로 다른 파일이다. 이 화면은 계획에 저장된 GLB를 그리며 USD 원본을 직접 브라우저에서 재생하지 않는다.
- 구형 embed 주소는 standalone 화면 호환용으로만 남는다. Product Planner에는 생산 현장 iframe을 만들지 않는다.

## QA / 다음 업무
- 무iframe 직접 마운트: Product Planner의 활성 계획/재생 런타임을 같은 페이지 API로 전달하고 같은 문서의 Three.js scene이 GLB를 로드한다. BroadcastChannel은 별도 탭 동기화용으로 유지한다.
- 부지/공장 카메라는 카드의 표시 크기와 기기 배율에 맞는 해상도로 공통 WebGL 장면을 캡처한다. 공장 카메라 프레임은 해당 공장 설비와 작업물 범위에 맞춘다.
- 표/로그/SVG는 실행 중 100ms 간격, 설비 설명은 250ms 간격으로 갱신한다. 화면에 보이는 부지/공장 카메라는 최대 30fps로 갱신한다.
- 수정 전 자동 브라우저 측정: 4.006초에 3D 시간 변경 37회(9.24회/초), 브라우저 프레임 콜백 227회. 실제 이동 갱신 빈도와 화면 렌더링 빈도의 차이를 확인했다.
- 2026-09-30 수정: 독립 카메라는 production-scene의 동일 장면·재질·조명·모델을 공유한다. 구형 Details 뷰어 자동 로딩을 제거했다.
- 카메라 카드만 독립 상태를 가지며 보이는 카드만 최대 8fps로 갱신한다. 화면 밖 메인 3D 렌더링도 중단한다. 카메라별 GLB 다운로드, WebGL 컨텍스트 생성, 렌더러 리사이즈는 하지 않는다.
- 앞으로 진행하는 시간 동기화는 기존 런타임을 재사용하고 되감기에서만 재생성한다. 별도 부지/공장 UI는 삭제하지 않는다.
- 자동 브라우저 QA: 자동차 예시 선택 → 실행 → 6개 카드 스크롤 → 표시 모드 전환 → 일시정지 → 전체 보기 이동. 결과: 공유 카메라 6/6, GLB 13/13, 구형 뷰어 미로딩, 화면 밖 카드 렌더링 0회/800ms, JavaScript 오류 0건. 사용자 PC의 FPS는 별도 측정 전이다.
- 탭 네 개 보존, 메인 3D와 별도 부지·공장 카드 표시, 카드별 GLB 필터, 카메라 개별 조작, 재생 시간 연동, 계획 변경 시 카드 재생성을 확인한다.
- 다음: 전체 255분 계획 완료까지 재생해 부지 간 운송과 완제품 출고가 모든 해당 카메라에 반영되는지 확인한다.

## 2026-09-30 직접 렌더링 전환 검수

### 저장 계획 전달 회귀 수정
- UI와 렌더러 간 getPlan API가 없는 기존 캐시에서도 snapshot.planId와 저장 계획 ID를 대조하여 동일 계획만 복구한다. 다른 예시로 대체하지 않는다.
- Planner, Details, Multiview, 직접 렌더러 진입 스크립트 버전을 direct-plan-sync-4로 갱신한다.
- QA 절차: 자동차 계획 선택 → GLB 로드 → 재생/일시정지 → 저장 → getPlan 없는 구버전 제공자 재현 → 새로고침 → 동일 계획 ID 및 GLB 13/13 검증.
- 도움말/다음 업무: 빈 화면이면 페이지를 새로고침한다. 저장 계획을 삭제하거나 자동차 예시로 덮어쓰지 않는다. 반복되면 현재 계획 ID와 화면 로딩 메시지를 확인한다.
- 제품 Planner의 메인 생산 현장 영역에서 production-scene iframe을 제거했다. `product-planner-direct-scene.js`가 생산 현장 UI를 페이지의 Shadow DOM에 마운트하고, 기존 Three.js 엔진·장면·GLB를 직접 사용한다. E096/조립 셀 보조 Pilot iframe은 별도 검토 화면이라 유지한다.
- 동기화는 같은 문서의 `ProductPlannerPlayback` API가 활성 계획과 시각을 제공하고, 현장 엔진이 프레임마다 읽는 구조다. 부지별 독립 카메라는 같은 renderer/GLB 장면 API를 사용해 중복 모델 요청을 하지 않는다.
- 자동 검수(1680×1100, 자동차 예시): 메인 생산 장면 iframe 0개, Shadow DOM canvas 1개, GLB 13/13(실패 0), 부지·공장 카드 6개, 카드 표시 GLB 13/13, 재생 시간 업데이트 88회/1.52초(약 58fps), 일시정지 드리프트 0초, JavaScript 예외 0건.
- 시각 검수 파일: `direct-scene-main.png`(메인), `direct-scene-full.png`(페이지 및 카메라 카드). headless 브라우저에서는 제품/레이아웃 목록 API가 401이지만, 브라우저 저장 예시 계획과 현장 GLB 렌더링은 정상 확인했다. 이는 인증된 세션의 카탈로그 동작을 검증한 결과가 아니다.
- 배포는 정적 파일 교체만 수행했으며 서비스 재시작·빌드는 없었다. 변경분 백업은 `/opt/Resonance/projects/P006/backup/execution-unified-1790748975`에 생성했다(약 220KB).
- 원씽: 메인 장면은 Product Planner 안에서 직접 렌더링하고, 각 부지/공장 카메라는 동일한 GLB 장면을 공유한다. iframe 전환 없이도 계획 시간과 화면을 동기화한다.
- 깨달음: UI 조각만 옮길 때는 화면은 뜨더라도 엔진이 참조하는 숨김 제어 DOM을 빠뜨리면 계획 로딩이 멈춘다. direct mount는 화면 노드와 렌더러가 요구하는 내부 노드를 함께 유지해야 한다.
- 공격/방어 평가: 기능 확장성 85/100(기존 단일 Three.js 엔진·카메라 카드 재사용), 회귀 방어 90/100(Shadow DOM ID 격리·기존 실행 API 유지·정적 백업·자동 브라우저 검수). 인증된 사용자 세션의 카탈로그 API는 이 QA 범위 밖이다.
