# 자동차 주요 모듈 3D 조립 데모

## 사용 절차

1. [제품 플래너](product-planner.html)에서 `자동차 주요 모듈 조립 계획 (FUNCTIONAL_DEMO)`을 선택한다.
2. `공정·운송` 설정을 검토한다. 기본 일정은 편집 가능한 예시이며 제조사 실측치가 아니다.
3. `실행 검토` 탭에서 `전체 공정 애니메이션 재생`을 누른다. 3D 시연 모델과 부지 카메라를 준비한 뒤 0분부터 전체 계획을 재생한다. 자동차 계획은 실제 부품 GLB 없이도 시연 형상을 생성한다.
4. 재생 중에는 `일시정지`·`다음 단계`·배속을 사용할 수 있다. `일정만 실행`은 기존 2D 일정/흐름도만 실행할 때 사용한다.
5. 운송 중 모듈은 출발·도착 카메라 모두에 보이고 결합 단계 동안 조립 위치로 이동한다. 반복 재생은 전체 공정 버튼을 다시 누르면 0분부터 시작한다.

## 범위와 데이터

- 표시 Geometry는 Three.js 기본 primitive로 런타임 생성한다. 공급사 USD/GLB를 만들거나 원본 파일을 고치지 않는다.
- 12개 주요 모듈 그룹에 4개 휠을 포함한다. 현재는 차량 치수·설계 기준·기계 작동축·실제 정렬/충돌 검증을 포함하지 않는다.
- 제조/조달·운송·조립 시작/완료는 기존 컴파일 일정과 실행 시간을 사용한다. 무관한 asset relationship, layout, Production DB는 수정하지 않는다.
- 부지별 3D는 제품 모듈의 개략 staging/assembly 표시다. 실제 공장 레이아웃에서의 설치 위치는 아니다.

### 최종 실행 검증 · 2026-09-26

- 실제 페이지에서 `부지별 시연 카메라 로딩`을 두 번 실행해 재사용 후 렌더링이 유지되는지 확인했다.
- 세 부지의 같은 시뮬레이션 시간을 관찰하고 600× 배속으로 255.0분 완료까지 실행했다. 결과는 준비 12/12, 운송 중 0, 조립 완료 12/12, 완제품 출고 1/1이다.
- 시각 검수에서 차체·모듈 부지는 완료된 부품이 후속 운송·조립으로 빠져 빈 상태 안내가 표시되고, 완성차 조립 부지에는 가상 완성 형상이 표시됨을 확인했다. 중간 운송 시점에는 발송지·도착지 카메라에 운송 모듈이 함께 표시된다.
- 이 결과는 일정 기반 `FUNCTIONAL_DEMO` 실행이다. 실제 자동차 형상·차량 BOM·설비 적합성·물리 이송·기계 애니메이션·생산시간을 검증한 결과가 아니다.
- 수정 리소스: `product-planner-details.js`, `product-planner-multiview.js`, `product-planner.html`. 코드 배포는 정적 파일 교체이며 서비스 재시작이나 DB 변경은 수행하지 않았다.
- 자동화: JS 문법 검사 3개 통과, 계획/일정 테스트 15/15 통과.
- 서버 저장/복원 및 Omniverse/USD 결과는 이번 검증 범위 밖이다.

### 단일 버튼 전체 흐름 실행 · 2026-09-26

- `실행 검토 → 전체 공정 애니메이션 재생` 단일 버튼으로 별도 모델 로딩·실행 클릭 없이 시작했다. 화면에서 3D 가상 모델 생성 후 0분부터 재생되고, 중간 시간 79.7분에 제조/운송/조립 위치 변경 및 부지 카메라 동기화를 확인했다.
- 최종 상태: 입력 일정 `255.0/255.0분`, 부품 준비 `12/12`, 운송 중 `0`, 모듈 결합 `12/12`, 완제품 출고 `1/1`; 브라우저 계획 실행 상태가 완료로 로컬 저장되었다.
- 재생/완료 시 3D 화면을 시각 캡처했다. 본 파일에 언급한 600× 기준 계획 재생 계산은 `255 ÷ (600/60) = 25.5초`; 모델 준비 시간은 별도이고 이 숫자는 전체 측정 벽시계 시간 주장이 아니다.
- 이 검증은 전체 UI 시연 경로만 닫는다. 입력시간 기반 `FUNCTIONAL_DEMO`이며 실제 제조 공정·차량 BOM·설비 가동부·물리 이송 검증은 아니다.

### 부지별 설비 우선 카메라 · 2026-09-27

- 부지 카메라의 표시 대상을 3가지로 분리했다: `설비 보기`(기본), `설비·작업물`, `작업물 보기`. 각 카드에서 독립 선택/카메라 회전·확대가 가능하며 선택된 부지·종류의 객체만 Bounds 계산에 사용한다.
- 3개 부지 카메라를 실제 브라우저에서 로드하고 전체 255분 데모 실행 종료 후 카드별 설비 표시를 시각 확인했다. 첫 카드에서 통합 모드 전환 및 안내 상태 갱신도 확인했다.
- 실제 모델 연결 5/13 설비, 일정 연동 기계 동작 0, 제품 모델 0/12 상태를 숨기지 않는다. 화면에서 보이는 시연 모듈은 `FUNCTIONAL_DEMO`다.

### 전체 설비 화면 및 공정 추적 카메라 · 2026-09-27

- 원인: `followActiveEquipment`가 HTML에서 기본 체크되어 있어 재생 시 3D 카메라가 활성 공정만 따라갔다. 별도로 현재 선택된 `전기차 주요 모듈 조립 계획`의 설비 배정은 `0/13`, GLB 연결은 `0/13`이어서 설비 Geometry 자체가 없었다.
- 변경: 기본 카메라를 전체 배치 보기로 설정하고 `전체 배치 보기` 조작을 추가했다. 사용자가 `현재 작업 설비 따라가기`를 켤 때만 카메라가 활성 설비를 추적하며, 해제하면 전체 범위로 돌아간다.
- 변경: Overview Bounds 계산에서 표시 중인 모델만 세지 않고 로드된 모든 설비·부품 Geometry를 포함한다. 현재 시각에 보이지 않는 모듈이 있어도 전체 화면의 프레임이 특정 공정으로 축소되지 않도록 했다.
- 상태 문구: 실제 설비 Asset 배정 수와 GLB 경로 수를 별도 표시하며 미배정 설비는 3D에 표시할 모델이 없음을 설명한다. 카탈로그 후보는 자동차 설비 적합성이나 동작 검증을 의미하지 않는다.
- 검증: 2026-09-27 Production 페이지를 별도 브라우저 탭에서 열어 기본 전체보기 체크 해제, `전체 배치 보기` 클릭 후 추적 체크 해제 복귀, 저장된 계획의 설비 배정 `0/13` 표시를 확인했다. 별도 임시 탭에서 5개 시각화 후보를 연결해 GLB `5/5` 파싱 성공, 설비 배정 `5/13`, 부지 카메라 3개 표시를 확인했다. 최종 3D 프레임에 후보 설비 5개와 조립 완료된 가상 모듈이 함께 보였다.
- 후보 5개는 임시 탭에서만 입력하고 탭을 닫아 폐기했다. 사용자 계획·실행 저장·서버 DB·생산 자산은 변경하지 않았다. 후보 Asset의 자동차 공정 적합성과 설비 동작은 여전히 미검증이다.
