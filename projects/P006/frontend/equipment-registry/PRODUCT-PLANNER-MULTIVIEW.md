# 부지별 동시 카메라 설계 · 2026-09-25

실행 단계의 공통 재생 제어 바로 아래에 부지별 카메라 카드를 제공한다. 공장→siteId를 기준으로 모델을 분리하며, 모든 카드의 공정 시간은 기존 단일 Runtime을 사용한다.

## 화면·도움말·업무 길잡이
1. 제품·주요 부품에서 계획을 선택한다.
2. 부지·공장에서 공장별 소속 부지를 지정한다.
3. 공정·운송에서 실제 GLB 모델을 연결·적용한다.
4. 실행에서 부지 카메라 모델 로딩을 누른다.
5. 공통 실행/일시정지/다음 단계/초기화를 사용한다. 각 화면에서 드래그 회전, 휠 확대, 카메라 초기화가 가능하다.

## 데이터·구현 매핑
- sites.id ← factories.siteId ← process.factoryId / part.factoryId.
- 운송 완료 후 부품의 카메라 소속은 도착 공장으로 변경한다.
- 표시 화면: product-planner.html, 공통 스타일: product-planner-multiview.css.
- 카메라·상태: product-planner-multiview.js; 모델 Scene/Renderer: 기존 product-planner-details.js 공유.
- 추가 WebGL Context 없이 부지별 카메라를 순차 렌더하여 카드 Canvas에 복사한다. 카드 갱신은 최대 10Hz이다. 실제 동시 부지 수 성능은 별도 측정한다.
- 임시 카메라 방향은 화면 사용 상태로만 관리하며 새로고침 시 초기화한다.
- 실제 설비 가동 애니메이션, 실제 공장 Layout 좌표를 새로 생성하지 않는다. 기존 GLB 개략 배치와 공정 상태를 표시한다.

## QA·다음 업무
- 기존 공정 자동화 회귀 15/15 PASS, 신규 JS 문법 검사 PASS.
- 브라우저 부지 카드/공통 시간/모델 누락 안내 시각 검수 실시.
- 자동차 계획의 부지 카드 3개 표시 확인. 독립 QA 화면에서 실제 E034 GLB 2개 부지 렌더 확인: 화면별 배경과 다른 픽셀 13,096 / 13,441; 공통 시간 12.0분. QA 시간은 검증용 고정값이며 실제 생산 측정값이 아님.
- 검증 화면: product-planner-multiview-qa.html (원본 계획 저장 데이터 변경 없음). 실제 자동차 조립 동작 검증은 포함하지 않음.
- 연결 모델이 없는 부지는 명시적 안내, 애니메이션 OFF는 공정 상태만 유지.
- 다음 업무: 차량 부품 GLB 확보 및 실제 공장 Layout 좌표 연결, 다부지 3D 성능 측정, 카메라 설정 저장.

## 자동차 FUNCTIONAL_DEMO 통합 실행 확인 · 2026-09-26
- 제품 플래너에서 3개 가상 부지의 독립 카메라를 같은 실행 시계에 연결하고, 실제 배포 화면에서 카메라 반복 로딩과 시뮬레이션 완료까지 확인했다.
- 600× 재생 완료 시 공통 시각 255.0분, 제작/입고 12/12, 운송 중 0, 조립 12/12, 완제품 출고 1/1이었다.
- 중간 진행에서는 운송 모듈이 출발·도착 화면에 함께 표시됐고, 완료 화면에서는 부품이 조립 공장으로 이동·소비되어 원산지 화면은 빈 상태 안내, 완성차 조립 화면은 가상 완성 형상을 표시했다.
- 반복 로딩 안정화를 위해 Renderer 폐기 시 `forceContextLoss()`를 제거했다. Three.js 리소스는 폐기하되 재사용 Canvas의 WebGL Context는 보존한다.
- 한계: 가상 primitive 형상과 편집 가능한 예시 시간 기반이다. 실제 자동차 USD/GLB·실제 공장 위치·운송 물리·기계 동작·DB 저장은 이 PASS에 포함되지 않는다.
