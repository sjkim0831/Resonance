1. 전체 업무·사용 순서 — 장소 동기화 v3

계획 담당자: 저장 계획 선택 → 제품·부품 → 부지·공장 → 공정·운송·모델 → 저장·3D 적용 → 편집 접기 → 작업 장소 설정 → 저장·3D 적용 → 재생. 두 저장 버튼은 동일한 계획 ID와 공통 검증·저장 함수를 사용하며 별도 장소 배정본을 만들지 않습니다.

부지·공장 탭은 이름과 소속을, 작업 장소 설정은 공장 내부 구역·셀 위치·방향·공정 배정을 편집합니다. 장소에서 공정시간을 바꾸고 저장한 뒤 상단을 다시 열면 갱신된 값이 표시됩니다. 상단에서 이름을 바꾸고 적용하면 장소의 소속 이름도 갱신됩니다. 미저장 편집은 다른 영역에서 덮어쓰지 않도록 차단합니다.

QA: 양방향 동기화 검증 결과 · 작업 장소 화면. 다음 업무: 실제 계획의 부지→공장→구역→셀 배정과 운송 조건을 확인하세요. 저장은 현재 브라우저 기준이며 서버 DB 저장은 포함하지 않습니다.

2. 화면·데이터 설계 v2 — Product Planner 기준

정식 통합 화면: product-planner.html#process. 다른 주소로 이동시키지 않고 이 문서에서 생산 현장 디자인·중앙 WebGL 캔버스 1개와 기존 입력 UI를 함께 제공합니다. #product는 제품, #site는 부지·공장, #process는 공정 편집, #run은 3D 재생입니다. 저장 계획이 없는 경우 먼저 예시 또는 저장 계획을 선택하세요.

기존 Product Planner 입력 소스는 product-planner-editor.html 내부 편집기로 재사용합니다. 중복 3D와 내장 시연 iframe은 제외했습니다. 기존 product-planner.html은 서버에 백업했으며 저장 데이터는 이전과 같은 브라우저 저장소를 사용합니다.

계획 ID를 유지하고 적용 시 revision·updatedAt을 갱신합니다. 임시 편집은 저장소를 바꾸지 않습니다. 검증 후 p006-product-plans-v1에 저장하고 0분부터 재구성합니다. 다른 탭의 변경은 덮어쓰지 않습니다. 새 공정은 셀을 추가하고 기존 수동 셀은 보존합니다. 서버 DB·권한·API는 변경하지 않았습니다.

3. QA·검증 경계

실제 자동 테스트 결과 JSON · 편집 화면 · 3D 화면

독립 브라우저 QA 계획으로 임시 변경 보존, 취소, 명시적 저장, 공정시간 갱신, 부지·공장·부품·공정 확장, 잘못된 공정 차단, 동시 변경 차단, 재생·끝 시점·새로고침 복원을 확인합니다. 사용자 기존 계획은 변경하지 않습니다. 입력시간 기반 시연이며 실제 자동차 BOM·공정 적합성·기계 동작·물리 충돌은 검증하지 않습니다. 서버 카탈로그 일부 조회가 제한된 환경에서도 연결된 GLB 표시를 별도로 확인합니다.

4. 자동 생성·다음 업무

generate-integrated.cjs가 기존 Product Planner HTML/JS에서 통합 전용 산출물을 생성합니다. 소스 변경 후 생성·문법 검사·브라우저 QA·정적 파일 복사를 순서대로 실행합니다. 서비스 빌드는 필요 없습니다. 다음 업무: 실제 저장 계획 1개로 현업 입력값을 검수하고 통합 편집에서 배치·모델·녹화까지 전체 흐름을 추가 검증합니다. 장기적으로 iframe 어댑터를 공통 편집 컴포넌트로 추출할 수 있습니다.

원씽: 입력 계획과 재생 계획을 일치시킵니다. 핵심: 버튼 합치기가 아니라 명시적 적용 경계를 통해 편집 데이터와 화면 상태를 동기화합니다. 추가 유료 서비스 사용 없음(0원), 기존 서버 비용 별도.
