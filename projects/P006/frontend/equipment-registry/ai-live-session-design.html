설비 AI 작업 세션

설계·화면·백엔드·QA · 개정 2026-10-01

원씽: 조사 중 실제로 확인된 진행 이벤트와 사용자용 중간 응답을 작업 ID별로 저장하여 화면에 즉시 보여주고 새로고침 뒤에도 이어서 확인한다.

사용 절차

  1. 제품과 공정을 고르고 왼쪽 목록에서 설비를 선택한다. 대상 이름과 설비 ID를 확인한다.
  2. 참고자료 수집 또는 가동 정보 수집을 시작한다. Kilo GPT-6.1 Sol Fast가 작업 ID를 만든다.
  3. 실시간 작업 내역에서 경과 시간, 최근 갱신 시각, 검색어/URL, 검색 완료·실패, 응답 조각을 확인한다.
  4. ‘중간 응답 전문’을 펼쳐 현재까지 받은 사용자용 응답을 확인한다. 내부 추론과 비밀 값은 표시하지 않는다.
  5. 완료되면 보고서와 출처를 검토한다. 확인된 결과와 출처는 기존 참고자료 목록에 미검토 상태로 저장된다.

화면·API 계약

단계상태입력출력
참고자료 수집실행 가능설비·제품·공정·등록 링크/자료 이름검색 활동, 중간 응답, 보고서·출처 목록
3D 시안 5개생성 기능 미연결향후 참고자료와 외형 기준향후 5개 이미지 후보·차이점
USD 제작생성 기능 미연결향후 선택 시안·검토 치수향후 USD·GLB·썸네일
가동 정보 수집실행 가능설비·공정·참고자료가동 검색 활동, 중간 응답, 근거 보고서
애니메이션 제작생성 기능 미연결향후 검토 모델·가동 정의향후 설비 애니메이션·공정 미리보기

브라우저는 3초마다 로그인 사용자 전용 API에서 최근 작업 20개를 읽는다. 작업 파일은 계정별로 분리한다. 각 작업에는 마지막 갱신 시각, 최대 100개 활동, 최대 12,000자 중간 응답이 저장된다. Kilo 이벤트가 들어오는 시점에만 진행 상태가 바뀌며 임의 진행률은 표시하지 않는다.

자료 누적·삭제 규칙: 조사 보고서는 실행별로 보관하고 출처 URL은 중복 없이 누적한다. 각 자료 행에서 사용자가 직접 삭제할 수 있으며, 삭제된 URL은 기록을 남겨 다음 조사에서도 다시 등록하지 않는다. 목록에는 신규·중복 출처 수를 표시한다.

품질·보안·제한

  • 페이지 역할: 로그인한 설비 작성자가 조사와 결과 검토를 수행한다. 서버는 작업과 자료를 계정별로 분리한다.
  • 로그에는 공개 검색 도구 이름, 확인된 URL/검색어, 사용자에게 반환할 텍스트만 둔다. 내부 사고 과정은 숨긴다.
  • `sk-...` 형태의 문자열은 화면·저장 로그에 그대로 남기지 않는다.
  • 서버 재시작으로 중단된 작업은 실패로 복구하고 자동 재요청하지 않는다.
  • 현재 지원: 참고자료·가동정보 조사. 시안·USD·애니메이션 버튼은 아직 실행할 생성 API가 없다.

QA 검증 절차

  1. 모의 작업을 실행해 ‘시작 → 검색 중 → 검색 완료 → 중간 응답 → 완료’를 시간순으로 확인한다.
  2. 페이지를 새로고침하고 동일 작업 ID, 로그, 경과 시간이 다시 표시되는지 확인한다.
  3. 미지원 단계가 ‘기능 미연결’로 나타나고 클릭할 수 없는지 확인한다.
  4. 작업 실패/로그인 만료와 브라우저 오류를 구분한다.
  5. 실제 Kilo 실행은 별도 유료 요청이므로 필요할 때 대상 설비 1건으로 확인한다.
