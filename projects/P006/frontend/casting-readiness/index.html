14개 표준 신호

IN/OUT은 P006 기준입니다. OUT 시작/인계 요구도 이 단계에서는 PLC 내부 미러 태그를 읽기만 합니다. 정상값과 timeout은 설계 초안이며 현장 승인이 필요합니다.

전체 I/O 입력 양식 JSON

UNBOUND → BOUND → READ-ONLY VERIFIED → REAL

  1. UNBOUND: 장비·protocol·address/tag·읽기 권한 미확정.
  2. BOUND: 필수 바인딩 형식 검증 완료. 접속 성공·REAL을 의미하지 않음.
  3. READ-ONLY VERIFIED: 장비 식별·읽기 접속·태그 자료형·GOOD 샘플·timestamp 증거 검증.
  4. REAL: 실제 값 변화 + 작업물/공정 상관관계 + 최소3개 사이클 반복 + 현장 기준/검토 승인. 장비 쓰기는 계속 금지.

실제 collector 신뢰키는 등록되지 않았습니다. 테스트의 서명 키는 fixture 전용입니다. 현장 확인 후 관리자가 수집기 신뢰를 별도 설정해야 합니다. 주소·스크린샷·GOOD 문자열만으로 승격되지 않습니다.

증거 및 재검증

  • 장비/바인딩 hash·collector ID·원시 응답 hash·서명·UTC 시각·sample sequence를 검증합니다.
  • 주소 변경, 서명/원시 데이터 위변조, 증거 만료, MOCK 근거는 기존 REAL 판정을 유지하지 못합니다.
  • 안전 인터록 변화는 승인된 안전 시험 증거로 확인합니다. 증거를 만들기 위해 생산 중 가드를 열거나 비상정지를 유도하지 않습니다.
  • 서명은 수집기 출처/무결성을 보장할 뿐 실장비 신원을 자동으로 보장하지 않습니다. 현장 식별과 담당자 검토가 필요합니다.

실행과 저장

python3 qualify.py --signals signals.json --evidence evidence.json --trust /secure/collector-keys.json --output qualification.json

무네트워크 검증기이며 원자적 파일 교체로 결과를 저장합니다. 상태를 수동으로 REAL로 적어도 검증기는 입력 상태를 신뢰하지 않고 다시 계산합니다. 현재 결과는 qualification.json의 14 UNBOUND입니다.
