# 탄소배출 관리 업무 원장 v1 검토본

상태: `REVIEW_REQUIRED`  
설계 원천: `emission-work-master-ledger.v1.json`

## 업무 구조

1. 배출량 프로젝트 포트폴리오 관리
   - 프로젝트 생성·검색·담당자 배정
2. 탄소배출 프로젝트 수행
   - 조직·운영 경계 설정
   - 활동자료 수집·품질검사
   - 계수 매핑·Scope 배출량 산정
   - 독립 검증·보완 판정
   - 보완·재산정
   - 검토·승인·결과 잠금
   - 보고·제출·인증서 발급

내부 하위 프로세스는 `조직·운영 경계`, `활동자료`, `산정·검증·승인` 3개이며 사용자에게 별도 최상위 업무처럼 중복 노출하지 않습니다.

## 구현 원칙

- 원장 승인 전에는 DB·화면을 대량 생성하지 않습니다.
- 승인 후 원장 한 건의 변경이 SDUI/JSON Form, 메뉴, 권한, API, Flyway, 도움말, QA, 업무 길잡이, 전체 업무 보기 및 자동 테스트에 증분 반영됩니다.
- 화면과 프로세스가 서로 다른 진실을 갖지 않도록 모든 생성물에 동일 추적 ID를 유지합니다.
- 회사 마스터 관리자는 액터 배정을 담당하고, 일반 업무는 사용자 화면에서 릴레이로 수행합니다. 관리자 화면은 설정·감사·예외 복구 용도입니다.

## 승인 전에 채워야 할 항목

1. 기능별 endpoint와 HTTP method
2. 기능별 DB read/write lineage
3. 회사별 권한 scope와 명시적 deny
4. 실제 메뉴 코드와 화면 리소스 ID
5. 정상·보완·권한·중복요청·복구 테스트 fixture

이 5개가 채워져야 원장을 `DESIGN_APPROVED`로 올리고 코드 자동생성을 시작할 수 있습니다.

## 실제 구현 추적 결과

`emission-function-traceability.v1.json`으로 40개 화면 기능을 실제 컨트롤러·서비스·DB에 대조했습니다.

| 판정 | 개수 | 의미 |
|---|---:|---|
| IMPLEMENTED | 32 | 사용할 수 있는 실제 API와 DB 계보가 확인됨 |
| PARTIAL | 3 | API는 있으나 업무 계약을 분리·보강해야 함 |
| GAP | 5 | 전용 API가 없어 구현이 필요함 |

우선 구현할 GAP는 프로젝트 책임자 재배정 1개와 관리자 액터 배정·SoD·권한 미리보기 4개입니다. PARTIAL은 계산 제출, 보완 finding 연결, 승인과 결과 잠금 분리입니다.
