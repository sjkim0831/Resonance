# LCIA 영향평가 화면 설계 (H1030302)

## 1. 목적과 범위
- 주소: `/lca/impact-assessment?projectId={projectId}`; 구 주소 `/emission/lca?menu=H1030302`는 프로젝트 ID를 보존해 새 주소로 이동합니다.
- 프로젝트별 LCI 산정 결과를 근거로 LCIA 방법·데이터셋 버전, 영향범주 결과, 검토 이력을 한 화면에서 확인합니다.
- 서버에 저장된 값만 노출합니다. UI에서 특성화 계수나 점수, 단위 또는 결과를 생성하지 않습니다.

## 2. 업무 흐름
1. 프로젝트 목록과 사용자의 접근 가능 범위를 서버에서 조회합니다.
2. `LCA_CALCULATION_RESULT`에서 동일 프로젝트의 LCI 저장본 전체를 조회하고, 작업자가 대상 workspace ID·게시 버전을 선택합니다.
3. 선택한 LCI workspace ID·버전·상태를 평가 설계 및 검토 JSON에 고정합니다. 최신본을 자동으로 바꿔치기하지 않습니다.
4. `LCA_IMPACT_ASSESSMENT` 저장본의 방법론·데이터셋·실행 식별자·범주별 결과·감사 정보를 표시합니다.
5. 완료·검토 상태, 결과 행, 실행 ID, 입력 해시를 별개로 확인합니다.
6. 검토용 JSON을 내려받거나 이전 LCI 산정 화면으로 돌아갑니다.

## 3. 화면 구성 및 업무 단계
1. 본문은 영향평가 업무 중심으로 구성하며, 프로젝트 선택 후 입력 LCI 산정 결과/버전을 고정합니다.
2. 방법론명·버전, 특성화 데이터셋명·버전·출처, 영향범주, 선택 시나리오를 프로젝트 단위 초안으로 저장합니다.
3. 영향평가 실행 영역은 입력 LCI·방법론 준비 상태를 표시합니다. 실제 계산 API와 계수 카탈로그 연결 전에는 실행을 잠급니다.
4. 영향범주별 결과 표는 서버에 저장된 범주, 지표, 값, 단위, 평가방법만 표시합니다. 미저장은 빈 상태로 설명하며 임의 샘플/0을 만들지 않습니다.
5. 사전 점검 6개 항목, 업무 순서, 완료 기준, QA/감사 상세는 접힌 도움말 영역에서 확인합니다.
6. 감사 정보에는 선택 LCI/LCIA 버전, 실행 식별자, 갱신 시각을 표시합니다.

## 4. 권한과 데이터
- 프론트 요청은 세션 쿠키와 CSRF 헤더를 포함합니다. LCIA 설계 저장은 서버에서 `LCA_SPECIALIST` 역할과 해당 프로젝트의 유효한 액터 배정을 모두 검사합니다. 시스템 `webmaster`는 기존 시스템 관리자 예외를 따릅니다.
- 대상 API: `/home/api/emission-projects`, `/admin/api/admin/lca-workspaces/LCA_CALCULATION_RESULT`, `/admin/api/admin/lca-workspaces/LCA_IMPACT_ASSESSMENT` 및 선행 입력 작업공간.
- 프로젝트 ID 일치 행만 화면에 표시합니다.
- 개발 브라우저 세션은 미인증 상태여서 사용자별 화면, 저장 성공 및 프로젝트 간 격리 E2E는 검증하지 못했습니다. 소스에는 서버 액터·프로젝트 배정 검사를 추가했습니다.

## 5. 기능 준비도와 미해결 계약
- 목록·결과 조회 UI, 저장값 파싱, 프로젝트별 평가 기준 초안 저장은 구현되었습니다. 저장은 기존 `POST /admin/api/admin/lca-workspaces/LCA_IMPACT_ASSESSMENT`를 사용하고 `businessKey={projectId}:LCIA`, `assignedActor=LCA_SPECIALIST`로 버전 레코드를 생성·갱신합니다.
- LCIA 산정 실행, 방법/특성화 데이터셋 카탈로그, 결과 원자적 저장·불변 버전·감사 증적 API는 개발 서버 코드 검색에서 찾지 못해 실행 버튼을 잠금 처리했습니다. 확인된 범위는 `LcaWorkspaceExecutionService`의 작업공간 종류 선언/설정 저장·액터 검사뿐이며 계산 API는 아닙니다.
- LCI 결과가 여러 버전이면 작업자가 선택하며, 저장 payload에 `inputLciWorkspaceId`, `inputLciVersion`, `inputLciWorkflowStatus`를 기록합니다. 내보내기도 선택 버전만 표시합니다.
- 화면을 실제 LCIA 업무형으로 재구성했습니다. 상단 4단계 카드와 본문 6개 점검 카드는 제거하고, 프로젝트별 LCI 입력 고정 → 평가 기준 설정 → 계산 실행 상태 → 영향범주별 결과 표 순으로 배치했습니다. 상세 QA/점검은 접힌 도움말로 옮겼습니다.
- 방법론·데이터셋 값은 사용자가 승인 근거를 확인해 입력하는 설계 초안이며, 카탈로그에서 검증된 선택값이 아닙니다. LCI 연결, 방법론·범주 및 특성화 데이터 검토, 실제 엔진 API가 확인되기 전까지 LCIA 점수는 비어 있으면 “미저장”으로 표시하고 0으로 간주하지 않습니다.
- 실행 활성화 전 필요한 계약: 방법/데이터셋 승인본, 버전 고정 LCI 입력, 서버 계산 endpoint, idempotency, 권한 재검사, 저장된 실행 ID/hash, 롤백/재실행 규칙.

## 6. 완료·QA 기준
- LCI 승인 결과 및 입력 버전이 프로젝트와 연결됨.
- 방법과 특성화 데이터 버전이 명시되고 모든 필수 범주에 값·단위가 있음.
- 재실행할 수 있는 실행 ID와 입력 해시, 계산 버전이 저장됨.
- 수행자·검토자·승인자 권한 분리 및 감사로그가 검증됨.
- 직접 접근, 새로고침, 메뉴 이동, 다른 프로젝트 격리, 무권한 차단, 빈/오류 응답, JSON 내보내기 테스트가 통과됨.

## 7. 변경 이력
- 2026-10-01: 프로젝트별 LCIA 화면, route/manifest, 구 주소 호환 이동, LCI 산정 다음 링크 추가. 이어 방법론·데이터셋·영향범주 설계 입력과 서버 버전 저장, 프로젝트 액터 범위 검사, LCI 버전 선택·고정, 감사 내보내기를 추가했습니다. 화면을 평가 입력·실행 상태·실제 저장 결과 중심으로 재배치하고 상태/점검 카드를 접힌 QA 도움말로 이동했습니다. 계산 엔진과 특성화 데이터 카탈로그 API는 미구현이며 브라우저는 로그인으로 리다이렉트되어 실제 LCIA 계산 및 업무 E2E는 미검증입니다.
