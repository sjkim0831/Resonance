# LCA 민감도 분석 화면 설계

## 목적

고정된 승인 LCIA 결과와 입력 LCI 버전을 기준으로 단일 입력 변수의 변화 범위를 정의하고, 계산 엔진이 저장한 영향범주별 결과를 검토한다.

## 업무 순서

1. 사용자는 권한이 있는 프로젝트를 선택한다.
2. 프로젝트의 승인·검증 상태 LCIA 결과와 연결된 LCI 스냅샷을 고정한다.
3. 원료·보조재, 에너지·스팀, 운송 작업공간에서 수량과 단위가 확인되는 변수를 선택한다.
4. 하한·상한 변화율과 변경 근거를 입력하고 조건 초안으로 저장한다.
5. 민감도 계산 서비스가 기준·하한·상한을 각각 재계산해 결과와 실행 ID를 저장한다.
6. 사용자는 영향범주별 값·단위·변화율·증적을 검토하고 결과 해석·개선안 업무로 넘긴다.

## 입력 계약

- `projectId`
- `baselineLciaWorkspaceId`, `baselineLciaVersion`, `baselineWorkflowStatus`
- `inputLciWorkspaceId`, `inputLciVersion`
- `variable.id`, `variable.group`, `variable.value`, `variable.unit`, `variable.sourceVersion`, `variable.evidence`
- `lowerPercent`, `upperPercent`, `rationale`

## 출력 계약

- 조건 초안 저장: 프로젝트·기준 버전·입력 버전·변수·범위·사유·저장 버전
- 실행 결과: 실행 ID, 기준값·변경값, 영향범주, 결과값·단위, 변화율, 계산 상태, 근거 해시

## 계산·저장 경계

현재 화면은 프로젝트·LCI·LCIA 작업공간을 조회하고 `LCA_SENSITIVITY_ANALYSIS`에 조건 초안을 저장하도록 구성한다. 민감도 계산 API와 결과 저장 계약은 확인되지 않았으므로 실행 버튼은 잠겨 있다. 프런트에서 기준 LCIA 결과에 변화율을 곱해 환경영향 결과를 추정하지 않는다. 계산 API가 연결된 뒤에는 입력 해시, 실행 ID, 원본 버전, 범주별 결과를 검증해야 한다.

## 완료·QA 기준

- 승인되지 않은 LCIA 저장본은 기준으로 선택할 수 없다.
- 입력 변수는 프로젝트 범위의 저장 자료이며 수량·단위가 확인되어야 한다.
- 하한은 0% 미만, 상한은 0% 초과이고 하한은 상한보다 작아야 한다.
- 프로젝트·LCI·LCIA 버전이 실행 전후 동일하게 고정되어야 한다.
- 실행 결과는 저장 후 재조회되어야 하며, 결과가 없으면 0으로 표시하지 않는다.
- 직접 URL 진입과 새로고침, 프로젝트 변경 시 상태 초기화, 권한 거부, API 오류, 조건 초안 저장·재조회, 결과 증적 내보내기를 확인한다.
