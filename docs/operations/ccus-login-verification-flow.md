# 로그인 버튼 통합인증 연결 — 2026-09-06

## 최종 정책: 비밀번호 로그인 재개
사용자 요청으로 로그인 버튼의 통합인증 선행 호출을 해제했다. 일반 및 관리자 모두 기존 비밀번호 로그인과 계정/MFA 정책을 사용한다. 일반은 /home, 관리자는 /admin으로 이동하며 authChoice는 건너뛴다. 별도 통합인증 버튼은 유지하며 당분간 금융인증서 사용을 도움말에 안내한다. 인증수단을 강제로 금융인증서로 고정하지는 않았다. 모의 브라우저 테스트 2건에서 인증 API 호출 없이 비밀번호 로그인 1회 후 각 홈 이동을 확인했다. 설치 및 테스트 명령 2.80초. 실제 사용자 로그인은 추가 확인 필요. 이전 정책 설명은 이 절에 의해 대체된다.

## 최신 변경: 로그인 완료 목적지
일반 로그인 완료는 /home, 관리자 로그인 완료는 /admin으로 이동한다. 영문 경로도 동일하게 유지한다. 로그인 결과의 certified 값에 따른 authChoice 이동을 제거했으며 authChoice 화면 자체는 변경하지 않았다. 관리자 로그인도 공통 통합인증 컴포넌트를 사용하며 관리자 경로를 언어 변경과 HTTPS 전환에도 보존한다. 기존 서버 및 관리자 라우트 권한 검사는 변경하지 않았다. 일반 흐름 6건 모의 테스트 및 관리자 로그인 후 /admin 이동 1건 모의 테스트 통과. 실제 관리자 인증 E2E는 사용자 확인 필요.

## 적용 설계
사용자는 HTTPS 로그인 화면에서 아이디와 비밀번호를 입력한 뒤 로그인 버튼을 클릭한다. 통합인증 SDK 창에서 인증하고 서버 검증이 성공한 경우에만 기존 비밀번호 로그인 API를 호출한다. 계정 상태와 기존 MFA 정책은 유지한다. 취소 또는 인증 실패 시 로그인 API는 호출하지 않는다.

/signin/authChoice 화면은 변경하지 않았다. 입력값 변경으로 자동 로그인 API를 호출하던 경로는 중단하고 명시적 클릭을 요구한다. 인증 진행 중 로그인 버튼을 비활성화한다. 도움말도 이 순서로 수정했다.

## 범위와 제한
이 변경은 프론트엔드 로그인 순서 변경이다. 백엔드 전체에서 통합인증을 필수화한 보안 정책은 아니다. 테스트 채널이며 인증정보와 계정을 영구 연결하지 않는다. 모바일 리다이렉트 후 자동 로그인은 미완료이다. 비밀번호는 URL이나 저장소에 추가 저장하지 않는다.

## 검증
실제 서비스 URL을 여는 브라우저에서 SDK와 API 응답을 모의 처리했다. 로그인 버튼 클릭 기준 성공, 비밀번호 실패, MFA, 공급자 실패, 취소, 비정상 로그인 응답의 6건 모두 통과했다. 취소 및 공급자 실패는 로그인 API 호출 0건이다. 전송·설치·테스트 명령 전체 약 5.56초. 실제 사용자 인증 로그인 E2E는 미검증이다.
