# 배출량 프로젝트 등록 완성에 필요한 화면과 업무

검토일: 2026-09-08. 소스 라우트, 실제 화면 구현, DB 프로세스 및 화면 연결을 대조했다. 등록 상태 VERIFIED는 기존 메타데이터 값일 뿐 이번 E2E 통과 증거가 아니다.

## 원씽
사업장 1곳·1개월·전기 자료를 프로젝트에 연결하여 원본→매핑→계수→결과를 추적 가능하게 한다. 이후 사업장 2곳으로 확장한다.

## 필요한 화면 (기존 경로 재사용)
|순서|화면|경로|필요 기능·출력|현황|
|---|---|---|---|---|
|선행|사업장 원장|/admin/emission/site-management|사업장 등록, 기업 소속·권한 검사, siteId|기존 화면 있음|

신규 URL 남발 금지: 원본 열 매핑은 기존 업로드 화면을 확장한다. 근거 추적도 기존 결과 화면을 확장한다. API의 저장 계약·사업장별 행 귀속이 먼저 필요하다.

## 프로세스 등록 결과
기존 EMISSION_PROJECT 하위 화면 연결 7건을 추가/갱신했다: 목록, 사업장 원장, 등록, 상세, 업무 배정, 엑셀 업로드, 산정 결과.
조직경계 화면의 안내 순서를 등록 후로 조정했다. 기존 실행 상태·결재·담당자·기본 프로세스 전이는 변경하지 않았다.
등록 화면은 projectId가 없을 때, 후속 화면은 projectId가 있을 때 진입하도록 조건을 명시했다. 사업장 원장은 권한 있는 관리자만 사용한다.
검증 상태는 SOURCE_AND_ROUTE_AUDITED_NOT_E2E로 기록했다. 전체 업무 보기의 실제 표시와 필터 반영은 별도 시각 검수 필요.

## 누락·불일치
1. 생성 단계에서 담당자와 검증 기준을 전부 필수 요구: 등록 단순화와 충돌.
2. 원본 열 매핑 부재: 고정 엑셀 열 순서는 사용자 파일을 매핑하는 기능과 다르다.
3. 활동자료 입력의 사업장 선택 부재: 프로젝트에 여러 사업장을 연결해도 행별 귀속을 확정하지 못한다.
4. 접수 전 계수 매핑 불가: 안내에 접수 단계를 누락하면 진행이 막힌다.
5. projectId 없는 후속 화면의 빈 상태/안내와 자동 기본 탭 처리가 필요.
6. 기준·목표 배출량은 산정 입력이 아니라 선택적 비교정보이며 생성 필수로 두지 않는다.

## 다음 구현 순서와 완료 조건
1. 기준정보 조회 오류 원인 확인 및 등록 API 필수 항목 정리.
2. 사업장별 활동자료 저장 계약: siteId 접근 검증·저장·조회.
3. 원본 열 매핑: 미리보기→검사→일괄 원자 저장→재조회. 재시도 중복 방지.
4. 결과의 사업장별 합계와 근거 추적.
5. 실제 계정으로 전 과정 저장·인계·보완·재산정 검수.

신규 기능은 아직 구현 완료로 표시하지 않았다. 기존 화면 존재와 업무 수행 가능성을 구분한다.
