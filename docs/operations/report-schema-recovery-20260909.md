# 보고·인증 현황 DB 구조 복구 · 2026-09-09

[배출량 현황](http://172.16.1.232/emission/index)

## 원인

실행 중인 보고 API가 참조하는 `emission_result_lock` 테이블이 로컬 PostgreSQL `carbonet` DB에 없었습니다. 관련 마이그레이션 3개는 배포 런타임에 있었으나 DB 적용 이력과 현재 소스 폴더에 없었습니다. 누락 시점이나 삭제 주체는 확인되지 않았습니다.

## 적용

원본 SQL의 정의를 그대로 사용했습니다.

1. V20260826213000: 산정 제출, 검증 지적, 결과 잠금 테이블·외래키·고유키·인덱스.
2. V20260827001000: 결과 잠금 버전·배출량·단위·스냅샷·해시·payload와 해시 제약.
3. V20260827003000: 보고서의 잠금 ID·해시와 외래키·해시 제약·인덱스.

런타임 계정 carbonet_app에 신규 3개 테이블 및 시퀀스의 필요한 접근권한을 부여했습니다. 기존 자료를 삭제하거나 승인·잠금 결과를 만들어 넣지 않았습니다.

## 안전 확인

- 변경 전 스키마 및 기존 보고 체인 데이터 백업: `/opt/Resonance/backups/20260909-report-schema`, 약 2.8MiB.
- 기존 보고서 2건, 산정 실행 2건, 제출 7건 확인. 보고서 2건 보존.
- 동일 DDL 트랜잭션 시험 적용 후 ROLLBACK 성공 → 실제 COMMIT.
- 잠금 대기 제한 5초, SQL 실행 제한 60초.
- 서버 재시작·전체 빌드 없음.
- 마이그레이션 원본 3개를 `apps/carbonet-api/src/main/resources/db/migration/postgresql`에 복구.
- Flyway 이력에 허위 성공 레코드를 직접 추가하지 않았습니다. 해당 SQL은 재실행 가능한 기존 정의입니다.

## 검증

- 인증 계정: webmaster.
- 7개 프로젝트 보고 API: 모두 HTTP 200.
- PRJ-2025-018: approved=null, reports=[] → 화면 승인 결과 없음, 보고서/확정 보고서/인증서 각 0건.
- PRJ-2026-001: 기존 보고서 2건 조회.
- PRJ-2025-018 검토 업무, 결과 잠금, 잠금 감사 조회 3개: 모두 HTTP 200.
- 업무 안내 5개 문장: DOM 내용·가시성·글자색 확인 및 스크린샷 검수.
- 7개 API 및 브라우저 확인 실행 약 0.92초(브라우저 종료 제외).

## 재발 감지

읽기 전용 검사 `/opt/Resonance/ops/tests/verify-emission-report-schema.sql` 추가 및 실행 통과. 핵심 3개 테이블, 해시 제약, 보고서→잠금 외래키, 런타임 권한 및 필요 컬럼을 검사합니다. 배포 파이프라인에 자동 연결한 것은 아니며 독립 실행 검사입니다.

## 범위 제한

조회 복구를 검증했습니다. 실제 제출→산정→검증→승인→잠금→PDF 발급 전체 업무를 이번에 실행한 것은 아닙니다. 승인·잠금 기록을 임의 생성하지 않았습니다. 회사 총배출량 중복 제거 집계 및 푸터의 예시 정보 정리는 별도 항목입니다.
