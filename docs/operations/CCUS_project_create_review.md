화면: http://172.16.1.232/emission/project/create

- 공통 EmissionPageIntro 사용, 흰색 본문, 1220px 최대 폭.
- 홈 → 탄소배출 관리 → 배출량 프로젝트 → 프로젝트 등록 브레드크럼.
- 착수 준비 진단 카드 및 착수 가능 배지 제거.
- 사업장 등록·관리 새 탭 링크. 입력 중인 기존 탭은 유지되지만 새로고침 전 입력값 보존은 아직 지원하지 않음.
- 기존 서버의 검증을 우회하지 않음. 등록 시 미충족 사유를 오류로 표시.

## 항목 분류 제안 (아직 저장 계약 변경 전)
1. 등록 필수: 프로젝트명, 소속 기업, 사업장 복수 ID, 보고연도/산정기간, Scope, 프로젝트 총괄, 마감일.
2. 산정 전 확정: 조직 경계, 적용 표준 및 버전, 자료 수집 주기.
3. 검증 업무 설정: 검증 수준, 중요성 기준. 일률적인 기본 5%가 업무별로 타당한지는 별도 기준 검토 필요.
4. 단계 진행 시 지정: 자료 담당자, 산정 담당자, 검증 담당자, 결재자. 등록 시 일괄 필수 지정은 사용자 운영방식과 불일치.
5. 추가 검토: 프로젝트 설명/목적, 기준연도(비교 업무 시), 사업장별 적용기간과 담당자, 임시저장.

## 복수 사업장 지원의 차단점
현재 EmissionProjectRegistryService.create는 contract.site() 한 개를 검증하고 emission_project_registry.site_name에 저장한다. 자료요청도 site 한 개를 사용한다. UI만 복수 선택으로 바꾸면 실제 연계가 성립하지 않는다.

필요 변경: 프로젝트-사업장 관계 저장 → 사업장별 접근권한 검사 → 목록/상세 재조회 → 사업장별 자료요청 → 집계 중복 방지 → 복사/삭제 처리.

최소 검증: 사업장 2개 등록 후 재조회, 둘 중 권한 없는 사업장 거절, 중복 선택 방지, 사업장별 자료요청 생성, 기존 단일 사업장 프로젝트 호환.

## 상태
복수 사업장 소스·DB·실행 서버 반영 완료. 실제 로그인 계정의 전체 저장 E2E는 세션이 없어 미완료.

## 복수 사업장 적용 결과
- 기존 대표 사업장 컬럼 유지. 추가 관계 테이블 emission_project_site에 사업장 ID, 표시명, 순서를 저장.
- 기존 프로젝트 7건의 연결 보존. 상세 API의 sites 배열 및 화면 표시 추가.
- 목록 표시·사업장 필터·프로젝트 복사도 복수 사업장을 사용.
- 선택 사업장의 회사·활성 상태 검사. 중복 선택 정규화, 최대 100개 제한.
- 사업장별 emission_project_activity_request 생성. 기존 통합 자료 요청은 프로젝트 단위로 유지.
- 기존 담당자 필수 지정·검증 설정 필수 규칙은 아직 유지. 단계별 지정을 완성하려면 후속 배정의 자료 요청 생성까지 별도 검증 필요.

## 검증 증거
1. Java 컴파일 및 입력 정책 검사 PASS (단일 호환, 복수, 공백/중복 정규화, 빈 값/잘못된 형식 거절).
2. 실제 DB 관계 테이블에 사업장 2개 연결·재조회 PASS. 검사 트랜잭션 ROLLBACK으로 원복.
3. 실제 공통 폼 컴포넌트의 사업장 2개 동시 선택 PASS. 별도 예시 데이터 화면이며 로그인된 실제 페이지 검수와 다름.
4. TypeScript 검사 PASS. 서버 재시작 후 health UP.
5. DB 연결 테이블 용량 24kB, Java 후보 클래스 296KiB.
6. 테스트용 로그인 세션 없음. 실제 API 등록→자료 요청→상세→삭제 E2E 미검증. 운영 사용자 데이터 임의 변경 없음.
