## 배치 및 데이터

- PostgreSQL16 기존 인스턴스35433에 독립 DB woosu_digital_twin 생성. CCUS carbonet DB 데이터는 수정하지 않음.
- 전용 DB 역할 p006_local_runtime 신규 생성. 기존 p006_app 역할이 있어 덮어쓰거나 비밀번호 변경하지 않음.
- 기존 프로젝트 SQL3개로 테이블12개와 역할·권한 초기값 생성. 이때 SET ROLE만 신규 전용 역할에 맞게 적용.
- 로컬 백엔드127.0.0.1:18086, p006-local-backend.service 자동 시작 및 실패 시 재시작.
- 소스: projects/P006/backend/P006LocalApplication.java 및 기존 apps/carbonet-api의 P006 컨트롤러2개.
- 실행물: /opt/p006-runtime/backend/classes. 기존 검증된 Java 라이브러리를 공유 사용하며 완전 독립 배포 패키지는 아님.
- 재컴파일: projects/P006/backend/build-p006-local.sh. CCUS 전체 빌드나 재시작 없이 P006 클래스만 컴파일.
- 프록시 /r/P006/* 목적지를 과거 Kubernetes주소에서127.0.0.1:18086으로 전환.

## 인증 및 비밀 관리

신규 관리자 p006admin, 무작위 비밀번호. 기존 계정 재사용 아님. BCrypt와 기존 세션 해시 검증 유지. 초기 관리자 생성 API는 root-only 환경파일의 별도 토큰이 없으면403. 웹 공개 자동 초기화를 허용하지 않음. 비밀번호는 별도 PRIVATE 파일로 제공하며 문서/로그에 기재하지 않음.

## 검증 절차

1. 신규 DB 초기 상태 확인.
2. 토큰 없는 bootstrap403.
3. 허용된 초기화로 새 관리자 생성.
4. 로그인 세션 authenticated=true.
5. 로그아웃 후 authenticated=false.
6. 틀린 비밀번호401, 올바른 비밀번호200.
7. 기본 장면 조회200.
8. 테스트 pump 객체 좌표10/20 저장200.
9. 재조회로 저장 객체 확인.
10. 테스트 객체 삭제200, 감사 기록 보존.
11. 로그아웃 후 장면조회401.
12. 실제 공개 주소 브라우저 로그인, 관리자 표시와 로그아웃 확인. pageerror0, 브라우저 측정673ms. 백엔드health UP.

## 완료 범위와 남은 작업

인증 및 기본 장면 API의 DB 연동 기반이 동작한다. 전체 P006 재구축 완료는 아니다. 시나리오 저장, 공개 장면 별칭, 설비·승인·USD 동기화 등 Python 스크립트에는 Kubernetes 의존성이 남아 있어 기능별 전환이 필요하다. Omniverse 스트림은 별도 준비/검증 필요. 이전 공장 USD를 새 DB 객체 데이터로 적재하지 않았음. 새 DB를 이전 데이터 복구본으로 표시하면 안 된다.

다음 핵심 작업: 기존 Python/프록시의 DB 의존 경로를 새 독립 DB로 전환하고, 시나리오·공장 설계 저장을 실제 사용자 흐름으로 검증. 배포 전 bootstrap 차단, 미인증401, 로그인·로그아웃, 장면 저장/조회 회귀 검사를 유지한다.
