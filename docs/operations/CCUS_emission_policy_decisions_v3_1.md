# CCUS 탄소배출 설계 정책 결정 v3.1

결정일: 2026-09-09. 사용자 위임에 따른 구현 기준. v3의 미확정 정책과 충돌하면 본 문서가 우선한다. 법정 의무 적합성 인증이 아니라 제품의 내부 운영 기본값이다. 실제 코드·DB·권한·삭제 정책 적용은 아직 하지 않았다.

## 1. 등록과 공유

- 등록 필수: 프로젝트명, 회사 소속의 활성 사업장 1~100개, 산정 시작일·종료일. 설명은 선택이다.
- 회사·생성자·생성시각은 서버 세션에서 기록한다. 등록 시 담당자·결재자·Scope·목표·기준 배출량·마감일은 받지 않는다.
- 같은 회사의 `emission.project.read` 권한자는 프로젝트 목록·상세를 조회한다. 모든 직원에게 권한을 자동 부여하지 않는다.
- 개인정보·상세 증빙 다운로드는 별도 권한과 사업장 범위를 적용한다. 프로젝트 조회 권한만으로 모든 증빙이 공개되지 않는다.
- 프로젝트 등록은 `emission.project.create`, 수정은 `emission.project.update` 권한으로 제한한다. 생성자가 자동으로 모든 후속 역할을 얻지 않는다.

## 2. 담당자·결재자

- 업무는 기본적으로 역할·사업장 권한으로 직접 진행한다. 개인 담당자 미지정만으로 차단하지 않는다.
- 업무 요청/인계를 사용할 때 담당자를 지정한다. 개인 지정 업무를 다른 사람이 처리하려면 권한 있는 관리자가 재배정하고 이력을 남긴다.
- 계산 작성자와 최종 승인자는 달라야 한다. 검토자는 계산 작성자와 달라야 하며, 검토자와 최종 승인자는 동일인도 허용한다. 따라서 내부 확정에 필요한 최소 인원은 2명이다.
- 최종 결과 잠금 및 공식 발급은 승인 없이는 불가하다. 1명만 사용 가능한 경우 입력·계산·초안 미리보기까지 허용하고 최종 발급은 대기한다.
- 사전 승인선은 등록 필수가 아니다. 검토 요청 때 권한 있는 검토/승인자를 선택한다. 역할·권한 없는 계정을 선택하여 권한을 얻는 방식은 금지한다.

## 3. 산정기간과 자료기간

- 프로젝트 기간은 시작일≤종료일이면 허용하며 연도 경계를 넘을 수 있다. 보고연도는 필수 입력하지 않고 기간에서 연도별 구간을 도출한다.
- 자료는 일자 또는 시작/종료일을 갖는다. 기존 YYYY-MM 자료는 해당 월 전체 구간으로 해석한다.
- 자료기간 전체가 프로젝트 기간 안에 있으면 그대로 사용한다.
- 부분월 또는 경계 중첩 자료는 자동 포함/자동 일할 배분하지 않는다. 실제 계량값 또는 사용자가 선택한 배분 방식과 근거가 필요하다.
- 일수 비례 배분은 사용자가 명시적으로 선택하고 근거·원량·원기간·배분일수·배분량을 기록할 때만 허용한다. 이를 측정값이 아니라 추정값으로 표시하고 검토 대상으로 분류한다.
- 같은 사업장·배출원·항목·기간·측정구분 중복을 검사한다. 다른 사업장 자료를 중복으로 판정하지 않는다.

## 4. Scope와 계산

- 사업장별 배출원 설정에서 Scope를 분류한다. 프로젝트 등록 시 Scope 선택으로 모든 사업장을 일괄 제한하지 않는다.
- 초기 화면은 Scope 1·2 배출원 설정을 먼저 안내하되 실제 배출원/활동자료를 자동 생성하지 않는다.
- Scope 3는 사용자가 해당 범위를 추가할 때 사용한다. 미등록/미포함 범위는 '미포함'으로 표시하고 0배출로 표시하지 않는다. 전체 Scope를 완료했다고 주장하지 않는다.
- Scope 2는 지역기반 결과를 기본 표시한다. 시장기반은 별도 방법 선택과 적격 근거·계수 검토를 거친 경우만 추가 계산하며 두 결과를 합산하지 않는다.
- 기준은 GHG Protocol 기반 내부 인벤토리로 시작한다. 이 기본값만으로 ISO 인증이나 규제 적합을 표시하지 않는다. ISO/규제 보고는 해당 양식·방법론을 별도 발행한 후 선택 가능하게 한다.
- 실제 계수·GWP 숫자는 코드에 임의 기본값을 넣지 않는다. 출처·단위·유효기간·버전이 발행된 기준값만 사용한다. 없으면 입력은 가능하나 계산은 차단한다.
- CO2e 계수에 GWP를 다시 곱하지 않는다. 가스질량 계수일 때만 선택된 GWP를 적용한다.
- 단위 정규화 후 decimal로 계산한다. 결과 저장은 tCO2e 소수 12자리, 반올림은 HALF_UP. 합계는 표시값이 아닌 저장된 항목 결과로 산출한다. 기본 표시는 소수 3자리이며 상세에서 저장 정밀도를 확인한다.
- 방법론이 더 높은 정밀도를 요구하면 명시적인 방법론 버전 변경으로 대응하고 과거 결과는 변경하지 않는다.

## 5. 기준연도·목표·대시보드

- 기준 배출량과 목표 배출량은 선택 비교정보다. 프로젝트 등록에는 넣지 않고 상세의 목표/비교에서 설정한다.
- 기준값은 확정된 이전 결과를 참조하거나 출처를 가진 수기값을 사용할 수 있다. 출처 종류를 표시한다.
- 여러 프로젝트 합산은 같은 사업장·기간·배출범위 중복을 검사한다. 중복이 있으면 사용자가 대표 결과를 선택하기 전까지 합산을 차단한다.
- 미산정·로딩·조회 오류·미포함·실제 0은 각각 별도 표시한다.

## 6. 보고·발급·공유·제출

- 초안 PDF 미리보기는 가능하나 '미확정 초안' 표시를 넣고 공식 인증서 ID를 만들지 않는다.
- 공식 발급은 승인·잠금된 결과만 사용한다. 원본 PDF와 발급 원장이 모두 저장돼야 발급 성공이다.
- 보고서 기본 양식은 내부 기업 배출량 보고서다. 사업장/기간/포함 범위/방법/계수 출처/계산 근거/제외·추정/검토·승인 이력을 포함한다.
- 규제 제출은 기본 미적용이다. 해당 기관·유형의 연결 계약이 준비된 경우에만 활성화한다. 수동 제출 기록과 외부 API 실제 접수를 구분한다.
- 다운로드 링크는 10분 만료를 기본으로 한다. 외부 공유는 기본 꺼짐, 명시 생성 시 7일 만료·즉시 취소 가능하게 한다.
- 공개 진위검증은 발급 식별자·발급/취소 상태·원본 일치 여부만 공개한다. 사내 상세 사업장 자료와 개인정보는 공개하지 않는다.
- 원본 해시 불일치와 서버 확인불가를 구분한다. 미등록 파일을 자동으로 진본/위조로 확정하지 않는다.

## 7. 마감·수정·재산정

- 마감은 적용된 업무만 검사한다. 미적용 규제 제출이나 LCA 업무는 차단 사유가 아니다.
- 제출·계산·승인·발급은 각각 불변 스냅샷이다. 원자료 또는 기준 변경 시 새 버전으로 재제출·재산정·재승인한다.
- 프로젝트 기간/사업장 변경은 자료 제출 전에는 revision 검사 후 허용한다. 제출 이후에는 영향 목록과 변경 사유를 기록하고 새 경계 버전을 생성한다. 과거 발급본은 그대로 보존한다.
- 재발급은 새 발급 ID와 이전 ID를 연결한다. 내용 변경 재발급은 이전 문서를 SUPERSEDED로 표시하고, 오류/철회는 사유와 함께 REVOKED로 처리한다.
- 차기 복사는 이름·사업장·배출원·기준 템플릿만 복사한다. 실제 활동량·계산·승인·발급 이력은 복사하지 않는다. 새 기간 유효성을 다시 검사한다.

## 8. 보관·용량·복구

- 업무 원본·제출·확정 결과·승인·발급 기록은 우선 프로젝트 마감 후 5년을 내부 검토기한으로 정한다. 법정 보관기간이라는 뜻이 아니다.
- 5년 도래 시 자동 삭제하지 않고 보관 정책·계약·법적 보존 필요를 확인하는 검토 큐로 보낸다. legalHold는 모든 정리를 차단한다.
- 업로드 미리보기 임시파일: 미참조 상태 24시간 후 정리. 실패 처리 임시파일: 7일 후 정리. 제출/발급 원본으로 참조된 파일은 대상에서 제외한다.
- 일반 기술 로그 30일, 상세 디버그 로그 7일, 보안/업무 감사 1년을 기본 검색 보관 구간으로 정한다. 기간 이후 업무 증거에 필요한 부분은 보관 큐로 보내고 승인 없이 삭제하지 않는다.
- 모든 자동 정리는 초기에는 dry-run만 실행하고 대상·용량·참조/보존 여부 검증 후 별도 활성화한다. 이번 설계 승인으로 과거 데이터 삭제를 실행하지 않는다.
- 소스·DB 변경 전 복구본을 남긴다. 파일은 hash 기반 중복제거를 하더라도 회사별 접근·참조를 분리한다.
- 실제 백업주기/복구목표는 일일 백업, 목표 RPO 24시간/RTO 4시간으로 설계한다. 운영 측정·복구 리허설 전 달성했다고 표시하지 않는다.

## 9. 화면 통합

- 09 프로젝트 설정 → 04 상세 편집.
- 23 기존 자료입력 → 22 활동자료 관리.
- 39 기존 결과 → 38 산정 결과.
- 46 기존 보고서 작성 → 45 보고서 작성.
- 50 인증서 후보 → 49 발급 관리.
- 호환 URL은 파라미터를 검사·전달하고 목표 화면으로 이동한다. 메뉴·팝업·도움말·설계·QA·길잡이를 같은 버전으로 동기화한다. 실제 사용처를 확인하기 전 코드는 삭제하지 않는다.

## 10. 적용 순서와 완료 조건

1. v3+v3.1을 구현 기준으로 삼아 01 목록→02 사업장→03 등록→04 상세부터 진행한다.
2. 정책·입력 DTO·DB 제약·API·화면·5종 안내를 같은 변경 단위로 만든다. 등록 UI만 단순화하고 서버 필수조건을 남기지 않는다.
3. 다사업장 자료/제출 스냅샷/산정 SQL/중복검사 B02~B04를 연결해서 해결한 뒤 계산 화면을 완료 처리한다.
4. 각 페이지 정상·권한거절·빈값·오류·저장/재조회·다음 화면 인계를 검증하고 컨펌받는다.
5. 현재 문서는 정책 결정이며 테스트 실행/법규 적합성 검증/배포 완료가 아니다.
